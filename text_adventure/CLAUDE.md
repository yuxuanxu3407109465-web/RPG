# 封城第七天：项目说明

现代丧尸末世背景的中文文字冒险游戏，开放世界，角色构筑参考 CRPG（辐射式属性 + 技能树）。
两人合作开发，通过 GitHub 同步。运行方式和文件结构见 README.md。

## 开发约定

- **必须兼容 Python 3.9**：macOS 自带的 `/usr/bin/python3` 是 3.9.6。不要用 3.10+ 的写法（`X | None` 类型标注、`match` 语句等），改完用 `/usr/bin/python3 main.py` 测试。
- 不引入第三方库，只用标准库。
- **内容放数据，规则放代码**：地点、物品、NPC、背景、技能、姿态都写在 `data/*.json`；公式集中在 `stats.py`。
- **物品全部在表格 `data/items.csv`**（2026-10 起，world.json 里不再有 `"items"`）：一行一件，中文列名、中文取值，Excel / WPS / Numbers 直接改，不用碰代码。读表、转换、检查在 `item_table.py`（`engine.World` 启动时读，转成和以前一样的物品字典，引擎其余部分不变）；写错了启动时列出“第几行哪一列”并拒绝启动（`main.py` / `webui.main` 先读一遍数据）。填写说明在 **`物品表说明.md`**。新增物品字段：`item_table.COLUMNS` 加列、`_row_to_item` 和 `to_rows` 两边都处理、说明里补一行。文档里其余提到“world.json 里物品的 xx 字段”的地方，现在对应表格里的列。
- 玩家看到的文字全部用中文；中文指令允许不加空格（如 `拿手电筒`），英文别名要用空格隔开。
- 存档（`saves/`）不进 Git。改存档格式时要兼容旧存档（参考 `Game.cmd_load` 和 `Character.from_dict` 的做法）。
- 技能数据在启动时会做引用检查（`SkillTrees._validate`），新增引用类字段时一并加检查。

- **所有数值计算一律向下取整**（伤害、闪避、检定修正、体力消耗与恢复、经验、物品效果、负重小数位等）。带小数倍率的先用 `Fraction` / `Decimal` 精确算再取整，避免浮点误差。

## 已确定的设计

### 角色创建
名字、性别（可自定义）、年龄、身高、样貌（自由填写）、背景（从选项中选）、属性分配、同伴（不带 / 预设 / 自定义）。
- **同伴暂时只有人类**：动物同伴（原来的预设同伴大黄）已去掉；**年龄、身高不设任何限制**（玩家和同伴都是自由填写，纯数字显示成“30 岁”“175 cm”，文字原样显示，`character.age_text` / `height_text`；只用于显示）。预设同伴暂时不补背景 / perk / 属性。
- **自定义同伴和玩家一样完整创建**：名字、性别、年龄、身高（自由填写）、关系、样貌、背景、perk、属性分配（`CharacterCreator._custom_companion`）。**标了 `player_only` 的背景 / perk 不对同伴开放**：灵能者背景，孤独之路、受欢迎两个同伴相关的 perk（`character_options.json`）。同伴背景的初始物品目前不发（同伴还没有背包）。`Companion` 新增的 `height` / `background` / `attributes` / `perks` 都有默认值，预设同伴和旧存档照常读。同伴的属性、perk 目前只记录和显示，**还没有任何效果**（同伴系统尚未设计）。

### 属性（创建时 3~10，5 为普通人）
力量、敏捷、体质、智力、感知、魅力。创建时每项默认 5、下限 3、上限 10，共 33 点可重新分配。
- **所有角色（玩家、敌人）的原始属性都不能超过 10**（`stats.ATTRIBUTE_MAX`）。其余加值（精英 / 首领的属性增强等）都算 **buff**：实际属性 = 原始属性 + buff（`stats.apply_buffs`），战斗等公式用实际属性，所以实际值可以超过 10。显示时拆开写，例如“力量 11（9 + 精英 2）”。
- **现阶段没有任何提升原始属性的手段**。读档时玩家的原始属性会被压回 1~10；敌人模板的原始属性超出 1~10 会在启动时报错。
衍生数值：负重、近战伤害、钝器精准（力量）；行动点、锐器精准、闪避、先攻（敏捷）；生命值、生命恢复、武术精准（体质）；经验倍率、每级技能点（智力）；枪械精准、闪避、先攻（感知）；同伴上限（魅力）。
- **生命值上限** = 10 +（体质 ÷ 2）× 等级（`stats.max_hp`）；升级时生命回满。
- **生命恢复**：每 10 回合恢复 体质 ÷ 2（向下取整）点生命（`stats.hp_regen`）；移动和 `等待` 都算回合。
- **同伴上限**：魅力每比 3 多 2 点多带 1 个同伴（3 → 0、5 → 1、7 → 2、9 → 3），`stats.companion_limit`。
- 所有属性在检定时的修正值 = 属性值 × 1.5（见“抛骰”）。

**属性部分的公式暂未最终确定**，计划等其他系统设计完后统一回头检查。

### 体力与时间（已实现）
- **回合制，不分战斗内外**（2026-10 改）：**1 回合 = 1 分钟**。每回合开始获得 敏捷×2（减重甲惩罚，最少 1）点行动点，没用完的留到下回合，上限 = 每回合获得量 × 2（`Game.ap` / `ap_gain` / `ap_cap`，存进存档，老存档读进来给满一回合）。**移动、拾取、使用物品、换装备、技能都花行动点**；时间只在回合结束时前进（`Game._pass_turn`：过 1 分钟、饿渴、回血、补行动点）。
  - **回合结束的三种情况**：玩家“等待 / 结束回合”（剩下的行动点保留）；行动点花到 0；**指令要的行动点不够**——先用剩下的行动点做掉一部分，结束回合，下回合补上剩下的（走路一格一格走，自然是先走一部分；一个动作就算“做了一半”，可能跨好几回合，例如重甲每回合只有 1 点时穿一件护甲要 6 回合）。统一走 `Game.spend_ap(cost)`，跨回合时在输出最后补一行“—— 回合结束，现在是……，行动点 X/Y ——”。
  - **消耗**（`stats.py`）：移动 1 格 1（超重 2）、拾取 1（`PICKUP_AP_COST`）、拿起 / 收起 / 换手武器盾牌 1（`HOLD_AP_COST`）、穿脱护甲 6（`ARMOR_AP_COST`）、背包饰品披风 1（`GEAR_AP_COST`，**暂定**）、使用物品 3（绷带等医疗物资也是 3，所有物品统一）、普通攻击 6、技能按各自 `ap_cost`。**背包里的操作**：不实际改变物品的（查看、拆分、堆叠、登记快捷栏）不花行动点，其余（放下 / 丢弃）暂定 1 点（`BAG_AP_COST`）。装备类指令**执行成功才扣**（`Game._with_gear_cost` 比较前后手上 / 身上的东西）；放下装备着的东西按卸下扣；说话、查看、切换姿态、拆分堆叠、存读档不花行动点。
  - **休息照旧快进**：休息 N 分钟 = 连续过 N 个回合，不花行动点；休克的强制休息同理。
  - 试攻击 / 试受击这类测试指令不花行动点。
- 体力上限 = 10 ×（体质 + 力量）：各 5 时 100，各 3 时 60（下限），各 10 时 200。带 buff 超过 10 时同样照算。
- **行动消耗不受属性影响**（2026-10 改：敏捷不再影响体力消耗，原来的「行动消耗倍率」连函数一起删了）。
- 走路消耗（室内外一样）：每 10 步 1 点体力（`Game.indoor_steps` 计数，存进存档）、每格 1 点行动点；超重翻倍。走路不再直接花时间。体力不够就走不动。`data/world.json` 里房间的 `outdoor` 标记现在只影响场景描述（障碍物那一类），不再影响消耗。
- 体力归零当场休克：失去行动能力，强制休息到上限的 30% 才醒，时间照常流逝。
- 体力低于上限 10% 进入力竭：攻击力 −50%，体力恢复后自动解除。**清除异常状态的道具清不掉这种力竭**，必须恢复体力；其它来源的力竭可以用 `Game.clear_condition("exhausted")` 清。
- **1 回合 = 1 分钟**：回合结束（等待、行动点用完、行动点不够）才算 1 分钟；**休息按分钟逐回合推进**（会触发回血、饿 / 渴掉血，中途死了就停下）。
- 休息：每半小时恢复 10% 上限，**一次可以休息 1 分钟 ~ 8 小时**（`engine.REST_MINUTES_MIN` / `REST_MINUTES_MAX`，8 小时一定够补满任何角色的体力）。**体力满了不阻止休息，只是体力不再涨、时间照走**（以前的实现是体力一满就提前结束，会把想靠休息推进时间的玩家卡住）。控制台写 `休息 90` / `休息 2小时`，网页上是滑条 + 快捷档位。
- 计时器从第七天 14:00 开始，显示“第 N 天 HH:MM”，跨过午夜进入下一天。**只有回合结束推进时间**（花行动点的指令把行动点花光时、等待、休息）。
- 走不通时的提示按房间数据来：房间的 `blocked` 写“墙壁”（室内）或“障碍物”（走廊、室外）。出口可以写 `danger`（一句描述），网页版会把这个方向标红。
- **每一步移动花掉多少体力、行动点写在正文里**：`移动至（第 X 列，第 Y 行），体力消耗 N，行动点 −1（行动点剩 X）`；没凑满 10 步的那几步不扣体力，N 写 0；行动点花到 0 时后面另起一行写“—— 回合结束…… ——”。换房间（`_travel`）时房间描述后面追加同样一句。写在引擎里是为了让网页版和控制台版共用。

### 技能树
- 花技能点解锁技能；初级技能 1 点，高级技能可能更贵。
- 初始技能点暂定 4（`starting_skill_points`），每级技能点公式暂定，都要等技能树设计完再定。
- **技能效果受所属技能树对应的属性影响。**
- 每棵树至少两条分支，分支只是侧重不同，不限制玩家混着学。
- **所有技能在没有特别声明的情况下，一律视为用主手武器发动。**
- **所有“解除”行为（解除 buff、解除姿态等）都不花行动点。**
- **不在自己行动回合触发的反应（反刃的反击、借机攻击等）不花行动点。**
- **格挡住的攻击算“没命中”**（例如会触发反刃）。
- **伤害修正分加算和乘算两类**（`stats.ADD` / `MUL`，修正写成 `(来源, %, 类别)`）：**力量、武器标签（锋利、沉重、背刺）、技能（姿态、暗袭、剜创……）的增伤全部相加**；**perk（绝境……）和状态（力竭）的增伤各自相乘**；**暴击最后再乘**。例：力量 +30%、锋利 +15%、进攻姿态 +20%、绝境 +30%、暴击 → (1 + 0.65) × 1.3 × 1.5。同一来源的多层（剜创 5 层 = +50%）当然也是相加。
- **“下一次……”这类储存型效果**（余势、连击的半价等）：**不能叠加 / 不能攒**，**本回合结束时没用掉就清除**（2026-10 改：原来是跨回合保留、战斗结束清除）。
- **主动攻击技能**（技能数据标 `attack: true`：随势斩、放血、剜创、盾击、焚化）没有特别说明时，**默认消耗 9 行动点、冷却到本回合结束**（本回合不能再用，下回合恢复，`skills.DEFAULT_ATTACK_AP_COST` / `TURN_COOLDOWN`）；单独写了的按写的来。目前：随势斩、放血、焚化 9 点 / 本回合；剜创 9 点、冷却 1 回合；盾击 6 点 / 本回合。
- **主动技能没有特别说明时，默认消耗 6 行动点、冷却到本回合结束**（`skills.DEFAULT_AP_COST` / `DEFAULT_COOLDOWN`，用 `skills.ap_cost(skill)` / `skills.cooldown(skill)` 读取；数据里写了就用写的，冷却写 0 表示没有冷却）。
- **敏捷 ÷ 4 这类分档的技能效果没有上限**：只看实际敏捷（原始属性 + buff），每满 4 点就再高一档。原始敏捷最多 10（第 3 档），但加上肌体硬化 +2 到 12 就是第 4 档，以后有加敏捷的装备 / 临时效果还能到第 5 档。写公式时**不要给档位封顶**（目前：随势斩横扫、撤步、卸刃无视护甲、反刃每回合次数）。**注意**：玩家的 buff 还没做出来，技能树里显示的数值目前按原始属性算。
- **原来“持续到战斗结束 / 整场战斗”的效果一律改为持续 25 回合**（`stats.EFFECT_DURATION_TURNS`；现在不分战斗内外）。
- 技能数据可以写 `ap_cost`（使用 / 激活本身的行动点）和 `cooldown`（冷却回合数），技能树界面会显示。
- **冷却 N 回合 = 使用那一回合之后再等 N 回合**：冷却 1 就是第 1 回合用、第 2 回合冷却、第 3 回合可以再用。
- 技能树：锐器（敏捷）、钝器（力量）、枪械（感知）、武术（体质）、潜行（敏捷）、生存（体质）、搜刮（感知）、交涉（魅力）、医疗（智力）、制造（智力）、武器掌握、灵能（特殊）。
- **武器掌握**：为不同的持握方式提供增益，分支是单手（一只手拿单手武器、另一只手空着）、双持、双手、持盾。**武器持握类的技能都放在这里**，不放进锐器、钝器等武器类技能树。对应哪项属性尚未确定（目前不对应属性）。当前持握方式用 `Game.grip_style()` 判断（徒手 / 单手 / 双持 / 双手；持盾等盾牌做出来后再加）。
- **灵能无法觉醒**，只有创建角色时选择"灵能者"背景才能解锁。
- 目前每个分支只先设计一两个技能来展示风格：
  - 锐器·**姿态流**分支（用重刃武器，主题：灵活切换姿态，同一招打出不同效果）：重刃姿态（进攻 / 防守 / 决斗，同时只能开一个，手持至少一把重刃即可，支持双持，切换不占行动）；随势斩（无姿态时为普通斩击，各姿态有不同额外效果）
  - 锐器·**弱点流**分支（用轻刃武器，主题：削弱敌人的薄弱之处、要害打击）：放血；反刃（被动，敌人攻击未命中——包括被格挡——时立刻用手上所有轻刃各反击一次，不花行动点，每回合最多 敏捷÷4 次，敏捷低于 4 时不触发）；剜创（主动，9 行动点、冷却 1 回合，目标身上每层持续伤害使这次伤害 +15%，技能增伤、加算）
  - 随势斩：横扫对每个目标 75% + 25% ×（敏捷÷4）的武器伤害（`stats.sweep_damage_percent`，敏捷 0~3 → 75%、4~7 → 100%、8~11 → 125%、12~15 → 150%……；和 100% 的差值算技能增伤、加算）；撤步后撤 2 + 敏捷÷4 格；卸刃无视 4 + 敏捷÷4 点护甲并尝试缴械——**缴械**：目标敏捷检定（d20 + 敏捷×1.5），难度 =（攻击者力量 + 敏捷）× 1.5（`stats.disarm_difficulty`），失败则武器掉在脚下。
  - 放血：**不无视护甲**（这一效果已取消），施加 2 层流血；每层**各自计时**，在目标回合开始时 4 点伤害、持续 3 回合，**不受护甲减免**（伤害类型“流血”）；最多 5 层（和其他持续伤害一致），满层时按通用规则结算最老的那层（`stats.BLEED_*`、`stats.blade_armor_ignore`、`bleed_max_stacks`、`sidestep_distance`）。随势斩、放血按攻击技能默认：9 行动点、冷却到本回合结束。
  - 技能树界面会自动列出技能提供的姿态及其数值（公式 + 按当前属性算出的结果），见 `stances.describe_granted`。
  - 灵能（只有灵能者背景能学），分支：**预言系、生物系、塑能系**。**前置顺序**：预言系 洞察 → 预判；生物系 肌体硬化 → 再生 → 代谢超载；塑能系 焚化 → 炽焰附魔。**灵能技能都可以对同伴使用**（增益、治疗类给自己或一名同伴；焚化这种伤害技能只能打敌人）。预言系·预判（所有针对目标的攻击处于**劣势**——命中判定 2d20 取低，持续 25 回合）、洞察（3 行动点、冷却 1 回合：给自己或一名同伴施加洞察效果，直到本回合结束，**拥有洞察效果的角色发起的所有攻击都获得优势**——2d20 取高，不再标记敌人）；生物系·肌体硬化（3 行动点，自身力量 +2、敏捷 +2（buff）、护甲 +4，持续 25 回合）、再生（只能治疗自己和同伴，回复 5 +（施法者体质÷4）× 等级 点生命并解除流血、中毒，`stats.psionic_heal`）、代谢超载（冷却 1 回合，持续 25 回合或主动解除：从下回合起每回合开始额外获得 敏捷 点行动点，**上限随之提高**（上限 = 每回合获得量 × 2），同时损失 敏捷×2 点生命；生命最多扣到剩 1 点，然后自动结束）；塑能系·焚化（9 行动点、冷却到本回合结束，范围 = 4 + 感知 格（`stats.incinerate_range`），只能对敌人使用，**不掷命中、必定命中、因此不会暴击**，6 + 等级 点火焰伤害并施加 2 层灼烧，`stats.psionic_bolt_damage`）、炽焰附魔（所有武器——双持两把都算——附火焰，持续 25 回合：命中额外 1d4 火焰伤害，**不吃任何修正**（力量、姿态、暴击都不算）、不受护甲减免；并叠 1 层灼烧：每层**各自计时**，4 点火焰伤害、持续 3 回合，最多 5 层，满 5 层时新的一层顶替最旧的）。没写的按默认 6 行动点、冷却到本回合结束。**这些都要等战斗流程和玩家 buff 做出来才真正生效**；优势 / 劣势已经在 `Dice.attack(advantage=/disadvantage=)` 里实现：取高 / 取低后的点数决定是否进入暴击确认，确认暴击那次正常掷；两者同时存在互相抵消。测试：`试受击 疾尸 劣势`、`试攻击 行尸 优势`。
  - 技能数据可以写 `value`（在 `skills.SKILL_VALUES` 登记），技能树会按角色当前属性算出数值显示。
  - 潜行：潜踪（被动，敌人的听觉范围（远）和警觉范围（近身）各缩小 2 格——**察觉系统尚未设计**）；暗袭（被动，偷袭时命中 +（敏捷 + 感知）÷ 2，伤害 +100%，技能增伤，属于加算类）。**只要目标还没发现你，就算偷袭**（察觉系统暂不设计）；测试：`试攻击 行尸 偷袭`。潜行树的分支尚未设计。
  - 武器掌握·单手：精通重击（被动，单手持用时暴击范围翻倍，18-20 → 15-20）、透甲（被动，单手持用时无视 4 点护甲）、余势（被动，单手持用时每回合一次：暴击后下一次攻击（普通攻击或技能）不花行动点；等战斗流程接上）
  - 武器掌握·双手：势大力沉（被动，双手持用时力量伤害**加值**每点 15% → 20%，力量低于 5 的**惩罚**每点 15% → 10%，`strength_damage_percent` / `strength_penalty_percent` 效果）；震倒（被动，双手持用时暴击后目标进行倒地判定（通用判定），失败则**倒地**：闪避 −6，一直持续到目标花 9 行动点爬起来（`stats.GET_UP_AP_COST`），爬起时引发借机攻击；等战斗流程接上）。
  - 武器掌握·双持：连击（被动，双持时**每次**主手攻击后，下一次副手普通攻击行动点减半，不限触发次数，`Game.offhand_attack_cost`）；双刃合击（主动，3 行动点、冷却 1 回合：激活后**本回合里所有攻击（普通攻击、技能、反击）都由两把武器同时发起**，每次消耗等于该攻击 / 技能本身的消耗，两把武器分别掷命中和伤害；**不再把两把武器的类型相加**，技能效果只对符合技能武器类型的那把生效；持续到本回合结束，不能叠加；**这一回合里连击完全不生效**、双武器攻击也不算副手出手）。连击：主手攻击包括普通攻击和技能，但追击只能是普通攻击。**以上要等战斗回合流程做出来才真正生效**。
  - 武器掌握·持盾：双重格挡（被动，持盾时每回合格挡次数 1 → 2）；盾击（主动，6 行动点、冷却到本回合结束：用盾牌发起一次攻击，**掷命中**——精准 = 体质 × 1.5 + 盾牌等阶加成（`stats.shield_bash_accuracy`），伤害 1d4 + 盾牌等阶加成、吃力量修正（`shield_bash_damage`）；**被命中**的目标进行体质检定（d20 + 体质 × 1.5），难度 =（攻击者 力量 + 体质）× 1.5（`stats.shield_bash_difficulty`），失败则获得**眩晕**：下回合最后一个行动；测试指令 `试盾击 壮尸`，末尾写数字连打几次，例如 `试盾击 壮尸 2`）。
- **盾牌**：物品带 `shield` 字段（内容可以为空）就是盾牌，按单手物处理，主手副手都能拿；任一只手拿着盾牌时持握方式为“持盾”（`grip_style` 返回 `shield`）。换双手武器会收起盾牌，反之亦然。目前样品：一楼大堂的防暴盾牌。盾牌本身会有属性，但暂时还没设计。
- **格挡**：持盾时每回合默认可格挡 1 次（`stats.BLOCKS_PER_TURN`）。敌人即将命中时自动进行格挡检定：d20 + 格挡修正，**敌方这次的命中（d20 + 精准）小于它就挡住**，攻击无效；掷出 20 必定挡住、1 必定挡不住；**敌人掷出 20（必定命中）时也可以格挡**。格挡修正 = 体质 × 1.5（向下取整）+ 力量（`stats.block_modifier`、`dice.Dice.block`）。测试指令：`试受击 壮尸 精英`（敌人打你一次，不扣血）。
  - **被动技能效果**写在技能的 `effects` 里（类型见 `stats.PASSIVE_EFFECTS`，可以用 `grip` 限定持握方式），引擎用 `Game.passive_effects(类型)` 取当前生效的效果；新增效果类型要在 `stats.PASSIVE_EFFECTS` 登记并在引擎里接上
  - 交涉分支：说服、威吓；钝器原来的持盾、双手分支已移到武器掌握。
  - 钝器（力量），分支 **横扫流**、**破甲流**（占位技能 blunt_1/2 已删）：全垒打（横扫流，9 行动点、冷却 1 回合：对近战范围内所有敌对目标攻击并尝试使其倒地——倒地按通用判定；本回合没移动过（`Game.moved_this_turn`，走路时置位、回合结束清零）伤害 +60%，技能增伤、加算，`stats.HOME_RUN_STILL_DAMAGE_PERCENT`）；粉碎（破甲流，9 行动点、冷却到本回合结束：无视 4 + 体质÷2 点护甲，`stats.crush_armor_ignore`；无视点数 ≥ 目标护甲时额外进行眩晕判定（通用判定）。
  - 武术（体质），分支 **强攻流派**、**游走流派**（游走流派尚未设计；占位技能 martial_1/2 已删）。**武术可以用武侠风的名字**（其他树不行）。**出招用手还是用腿，唯一标准是有没有“踢腿的武道家”**（`skills.uses_kicks`）；**技能名不随 perk 变，要取成看不出用哪个身体部位的名字**。排山倒海（强攻流派，id `martial_flying_kick`，原名飞踢，9 行动点、冷却 1 回合：距离 ≤ 2 + 敏捷÷4 格，有踢腿的武道家时 3 + 敏捷÷4（`stats.flying_kick_range`），突进到跟前攻击；被命中者体质检定，难度 =（攻击者 体质 + 力量）× 1.5（`flying_kick_difficulty`，和盾击同公式），失败被踢飞 2 + 攻击者体质÷4 格（`knockback_distance`）并倒地；踢飞路线上的其他目标受这一击 50% 伤害（乘算，`FLYING_KICK_SPLASH_PERCENT`）并同样检定，失败倒地）。**所有武术技能都要求主手不拿武器**（副手随意；技能树的 `unarmed_only`，`Game.main_hand_free_of_weapons`；盾牌不算武器，手电筒、撬棍这类代用武器算，双手武器占着主手所以不行），伤害按徒手攻击。
  - 读档时，存档里学过但技能树里已删除的技能会被去掉并退还技能点（`Game._load_skills`，旧占位技能按原价 1 / 2 点退）。
- 除锐器、钝器、武术外，其他树里的"入门 / 进阶"都是**占位技能**，等设计后替换。

### 战斗系统（基础数值已定，回合流程尚未实现）
公式和常量都在 `stats.py` 的“战斗”一节，命中判定在 `dice.Dice.attack`。
- **所有掷骰都用 d20**（战斗和检定）。
- **命中**：d20 + 精准 **≥** 闪避 即命中（等于也算，和检定统一）；掷出 20 必中，掷出 1 必不中。
- **精准** = 所用武器对应的属性 × 1.5，向下取整（和属性修正同一个公式，`stats.accuracy`）：锐器（重刃 / 轻刃）看敏捷、钝器看力量、枪械看感知、武术（徒手）看体质（`stats.WEAPON_ATTRIBUTES`）。没拿武器按徒手算。双持时每只手分别算。
- **闪避** =（敏捷 + 感知）× 1.5，向下取整（例如 16.5 → 16）。
- **先攻值** =（敏捷 + 感知）× 1.5，向下取整（`stats.initiative`，和闪避同一个数）。战斗开始时每个角色掷**先攻检定 = 1d20 + 先攻值**，高的先行动（`Dice.initiative`）；警觉 perk 掷 2d20 取高。**结果相同就双方重掷**（警觉的优势照样生效），直到分出先后。测试：`试先攻 疾尸`。
- **行动点**：每回合获得 敏捷 × 2；没用完的留到下回合，上限为每回合获得量的 2 倍。**不分战斗内外**，见“体力与时间”。
- **普通攻击**消耗 6 行动点。
- **近战武器默认射程 1 格**（`stats.MELEE_RANGE`）；踢击等特殊攻击可以更远。
- **远程武器的攻击范围 = 武器原始射程 + 感知 ÷ 4**（格，向下取整，`stats.ranged_attack_range`）。
- **角色的视野范围 = 4 + 感知**（格，`stats.sight_range`）。**射程不能超过视野**（`stats.effective_ranged_range`），以后可能加瞄准 / 侦察功能来突破。原始射程暂定：霰弹枪 2、手枪 6、突击步枪 6、狙击枪 10（`stats.FIREARM_BASE_RANGES`）。枪械的其他设计仍然暂缓。
- **等待 / 结束回合**：结束当前回合（过 1 分钟），没用完的行动点保留（受 2 倍上限约束）。网页版休息栏里的“结束回合”按钮。
- **行动点消耗**：普通攻击 6、移动 1 格 1、使用物品（例如用绷带包扎）3（`stats.ATTACK_AP_COST` / `MOVE_AP_COST` / `USE_ITEM_AP_COST`）。
- **武器伤害骰**写在 `data/world.json` 物品的 `weapon.damage`，按武器形制分档：**1d4** 匕首（所有匕首默认 1d4）；**1d6** 高暴击范围的单手武器、双手长柄武器；**1d8** 寻常单手武器；**1d10** 寻常双手武器（`stats.DAMAGE_TIERS`）。
- **武器标签**（武器数据的 `"tags"`，`stats.WEAPON_TAGS`，一件武器的具体特性由标签决定；启动时检查）：**长柄**（攻击范围 1 → 2 格）、**破甲**（无视 2 点护甲）、**要害**（暴击增伤 50% → 80%）、**锋利**（伤害 +15%）、**背刺**（偷袭时伤害 +200%）、**流血**（命中时给目标施加 1 层流血）、**招架**（拿着时闪避 +1）、**沉重**（精准 −6，伤害 +60%）。标签的增伤属于加算类。敌人拿到带标签的武器同样生效。**哪些武器带哪些标签**：所有**匕首**类 → 背刺；有破甲设计的（消防斧、战锤）→ 破甲；极为笨重的钝器（树干、路牌）→ 沉重；专门用来刺入人体的（骑士剑、手术刀）→ 锋利；高暴击范围的（弯刀，暴击 18-20 这类）→ 要害；能格挡的双手武器（撬棍）→ 招架。现有武器：军用匕首 背刺、要害——它是**高稀有度**的匕首，比寻常匕首（暴击 19-20、只有背刺）多了更宽的暴击范围（18-20）和要害标签；撬棍 招架；**弯刀**（单手重刃 1d6、暴击 18-20）要害，在街道；**祭祀弯刀**（高稀有度弯刀）要害、流血，在地下停车场；开山刀、手电筒无标签。测试：`试攻击 行尸 偷袭`。
- **代用武器**：本质是工具、不适合当武器用的东西（撬棍、手电筒、水果刀、擀面杖……），数据写 `"improvised": true`，**最终伤害降一档**（`stats.tier_down`：撬棍按双手 1d10 → 1d8；手电筒按 1d6 → 1d4）。开山刀是正经武器，1d8。名字原叫“简易武器”，改为“代用武器”。
- **伤害计算**（`stats.final_damage`）：骰出的伤害 ×（1 + 加算类之和）× 乘算类各自 ×（暴击时 1.5 / 要害 1.8），**向下取整**，再减护甲，**最低 0**。修正来源：力量（仅近战）、姿态（仅姿态要求的武器）、力竭 −50%。用 `Fraction` 计算，避免浮点误差影响取整。
- **暴击**：命中且 d20 点数落在武器的暴击范围内时，再掷一次命中判定确认：也命中就是暴击，伤害额外 **+50%**（“要害”标签的武器 +80%；在其他修正之后、护甲之前结算）；没命中就按普通命中处理（`dice.Dice.attack`）。掷出 20 只保证命中，是否暴击仍由第二次决定。
- **暴击范围**按武器类型（`stats.CRIT_RANGES`）：钝器和徒手 20；寻常锐器（开山刀等，重刃和轻刃都算）19-20；宽暴击范围的锐器（弯刀、反曲刀、军用匕首）18-20，基础伤害 1d6——这类武器在 `world.json` 里单独写 `"crit_range": "18-20"`、`"damage": "1d6"` 覆盖默认值。**枪械的全部设计暂缓。**
- **距离单位：战斗中用“格”，战斗外用“米”。**
- **所有持续伤害（流血、灼烧、强酸腐蚀……）机制完全一样**：在目标自己的回合开始时结算（不是整轮战斗的新回合开始时），每层各自计时，**最多 5 层**（`stats.DOT_MAX_STACKS`），不受护甲减免；**满层后再获得新的一层时，最老的那层立刻按 50% 结算剩下的伤害（每回合伤害 × 剩余回合 × 50%，`stats.dot_overflow_damage`），然后被新层顶替**——例：每回合 4、还剩 2 回合的流血立刻造成 4 点。
- **伤害类型**（`stats.DAMAGE_TYPES`）：物理、火焰。**护甲（伤害减免）只对物理伤害生效**，火焰等其他类型不受护甲影响（`stats.final_damage` 的 `damage_type`）。
- **护甲**提供固定减伤：身上所有部位的护甲值相加，每次受到的伤害减去这个总值。
  - 物品写 `"armor": {"slot": "head", "class": "light", "value": 2}`，用 `装备` / `卸下` 穿脱，每个部位一件，穿新的会自动换下旧的。
  - 护甲部位固定 **5 个：头部防具、身体防具、手部防具、腿部防具、脚部防具**（`world.json` 的 `armor_slots`，显示名都带“防具”后缀）。曾被误删的手部位已恢复；如果以后删掉某个装备位，旧存档里挂在那儿的装备由 `Game._load_worn` 自动放回背包。
- **其他穿戴位**（`world.json` 的 `gear_slots`，不提供护甲）：饰品 2 个、披风 / 斗篷 1 个、背包 1 个。物品写 `"gear": {"slot": "accessory"}`（或 `cloak`、`backpack`），同样用 `装备` / `卸下`；饰品先放空位，两个都满了换下第一个。
  - **背包减重**：背包写 `"weight_reduction": 20`（%），背着时背包里所有东西（包括背包自己）的总重按这个比例打折（`Game._carried_weight`），负重上限不变。
  - 饰品、披风目前没有任何效果，具体效果和各种背包的减重率尚未设计；游戏里还没有这类物品。
- **超重**（`stats.load_level`，按打折后的背包总重算）：超过负重上限 → 超重，移动能力减半（战斗中每格 2 行动点）；超过上限 2 倍 → 严重超重，完全无法移动（`走` 会被拦下）。正好等于上限 / 正好 2 倍都不算。
  - 超重也能继续拿东西，拿、放、换背包、卸背包后负重状态变了会补一句提示；超重和严重超重会出现在异常状态里（实时计算，不进存档）。
  - 超重：走路的体力消耗和行动点都翻倍（`stats.OVERWEIGHT_TRAVEL_MULTIPLIER` / `OVERWEIGHT_MOVE_AP_COST`）。
  - 类别（`stats.ARMOR_CLASSES`，启动时检查数值范围）：寻常服装 0；轻甲 1~3，按部位定（胸甲 3、鞋子 1）；重甲 2~6，会降低每回合行动点（每件写 `ap_penalty`，**每 1 点 = 行动点 −5%**，各件相加，`stats.armor_ap_percent`；例如防暴护甲 3 点 → −15%，全套 9 点 → −45%，敏捷 5 时每回合 10 → 5，上限随之变化）。**重甲每件扣多少行动点尚未确定**，目前游戏里没有重甲。
  - **装备等阶**（`stats.QUALITIES`，物品的 `quality`，不写就是普通）：破旧、普通、精良、传说。以普通为基准，每高一阶 +1、每低一阶 −1：**护甲**的护甲值 ±1（最低 0，`stats.armor_value`）；**武器**的精准 ±1、伤害 ±1（精良开山刀 1d8+1，破旧开山刀 1d8-1，`stats.weapon_damage`），敌人拿的武器同样适用。数据里写的是普通等阶的基础值，启动时按类别检查基础值范围。名字显示成“精良 防暴护甲”（普通不加前缀）。
  - 护甲可以写 `sight_penalty`（视野减少），视野 = 4 + 感知 − 护甲惩罚（`Game.sight_range`）。
  - 样品套装（普通等阶），各部位数值：**头部 = 腿部**、**手部 = 脚部**。
    - **骑行护具（轻甲，地下停车场）**：摩托车头盔 头 2、骑行夹克 身体 3、骑行手套 手 1、骑行护裤 腿 2、骑行靴 脚 1（全套 9）。
    - **防暴装备（重甲，一楼大堂）**：防暴头盔 头 4（行动点 −10%，视野 −2）、防暴护甲 身体 6（−15%）、防暴护手 手 2（−5%）、防暴护腿 腿 4（−10%）、防暴靴 脚 2（−5%）（全套 18，行动点 −45%）。
  - **重甲扣行动点（按百分比，向下取整）最多扣到 1**（`stats.ap_per_turn`），不会让角色一回合一点行动点都没有。
- **力量伤害修正**：力量每比 5 多 1 点，伤害 +15%；每少 1 点 −15%（力量 3 为 −30%）；势大力沉会把加值改成每点 20%、惩罚改成每点 10%。适用于所有近战武器（锐器、钝器、武术），**不适用于枪械**（`stats.melee_damage_bonus`）。
- 重刃姿态的加成是**固定值，不随属性变化**：进攻 近战伤害 +30%（技能增伤，和力量加算）、防守 闪避 +3、决斗 精准 +3。
- 姿态加成里的 `accuracy` 只加在姿态要求的那类武器上（决斗姿态只加重刃的精准），`dodge` 直接加闪避。
- 测试用指令：`试攻击 <闪避> <护甲>` 用手上的第一件武器试一次攻击，显示命中和伤害的完整计算过程（还没有敌人）。
- **距离与位置**：近战范围、后撤；移动能力受敏捷和穿戴装备影响。
- 借机攻击、护甲（及无视部分护甲）、缴械、持续状态（如流血：每回合掉血，持续 3 回合）。
- 其余数值（重甲的行动点惩罚、各部位护甲值、距离单位、技能的行动点消耗、护甲无视比例、流血伤害等）尚未确定，实现时先询问，不要自行编造。

### 眩晕与震慑
- **同名负面状态不管来源都用同一套判定**（`stats.STATUS_CHECKS` / `status_difficulty`）：**倒地、眩晕** = 目标体质检定（d20 + 体质 × 1.5），难度 =（施加者 力量 + 体质）× 1.5，失败就获得该状态。来源：盾击、粉碎（眩晕）；飞踢、全垒打、震倒（倒地）。以后加新的负面状态也照这个做：先在 `STATUS_CHECKS` 定一套判定，所有来源共用。
- **眩晕**（`stunned`）：下回合最后一个行动。**同一回合里第二次被眩晕，升级为震慑**（`dazed`）：跳过下一个回合；已经是震慑不会降回眩晕（`stats.stun_level`、`Enemy.apply_stun`，按 `Game.turns` 判断是不是同一回合）。**对玩家和敌人都生效**。来源目前只有盾击。玩家这边（`Game.stun_player` / `_tick_stun`，状态记在 `character.conditions`，进存档）：震慑在下一个回合开始时让那一回合直接跳过（**行动点照样获得**、只是不能行动，时间照走）；眩晕撑过下一整个回合后解除，“最后行动”要等战斗流程接上。测试 `试眩晕 2`。

### 死亡
- 生命降到 0 就死了（`Game.damage_player(数值, 死因)`，死因 id 见 `stats.DEATH_CAUSES`：饥饿、口渴、死于僵尸、死于掠夺者、生病、失血过多；目前只有饥饿 / 口渴真的会发生）。
- 死后弹出“你死了”菜单，写明死因，只能**读档**或**返回主菜单**（控制台 `main.death_menu`，网页 `state.death` + 浮层，`/api/menu` 回主菜单）；死了以后其它指令（包括方向、存档）一律拦下，读档成功就清掉死亡状态。

### Perk（开卡特质）
- 创建角色时在“背景”之后、“属性分配”之前选择，花 perk 点，perk 点不能为负。**一次选完再提交**：网页版是可多选的卡片（选中变绿，冲突 / 点数不够的变灰并写原因），选好点“继续”；控制台输编号切换、输“完成”结束（`Prompter.perks` / `WebPrompter.perks`，校验统一走 `CharacterCreator._check_perks`）。初始 perk 点 `progression.starting_perk_points` = **2**。**正面 perk（`kind: positive`，默认）花 1 点；有正有负的 perk（`kind: mixed`）不花点**；单独写了 `cost` 就按写的（`CharacterOptions.perk_cost`）。
- 写在 `data/character_options.json` 的 `perks`：`cost`、`description`、`effects`。效果目前支持：`attribute_points`（额外可支配属性点，加到属性分配总数里）、`perk_points`（额外 perk 点）、`no_companions`（无法携带同伴，同伴上限为 0，`CharacterOptions.companion_limit`）。
- 现有 perk：**孤独之路**（有正有负：+4 可支配属性点、+2 perk 点，无法携带同伴）；**早熟**（有正有负：+2 可支配属性点，经验获取 −20%，和智力倍率相乘）；**致命**（1 点：攻击命中时 5% 概率触发——对非首领立刻杀死，对首领改为这一击伤害 +100%；等战斗流程接上）；**警觉**（1 点：视野 +2，先攻检定优势——先攻检定等战斗流程接上）；**顽强**（1 点：每级生命上限额外 +2）；**踢腿的武道家**（有正有负：不能用枪械和近战武器，徒手变为踢击 1d6、射程 2；盾牌照样能拿）。
- 新增 perk：**受欢迎**（1 点：开局多带一名同伴，同伴上限 +1；和孤独之路互斥，perk 的 `conflicts`）；**绝境**（1 点：生命不高于 30% 时闪避、精准 +3，伤害 +30%——perk 增伤，乘算）；**残忍**（有正有负：寻常医疗物资——物品标签 `basic_medical`，例如绷带——治不了流血，要用医疗箱或灵能；自己造成的流血每层每回合 4 → 6）；**井井有条**（1 点：减重率 +20%，和背包的减重率相加，减重率没有上限，超过 100% 时重量按 0 算）。
- **刀锋舞者**（有正有负：无法使用枪械——装备时拦下；手持的重刃 / 轻刃同时视为重刃和轻刃，技能要求、姿态加成都按两种算，`Game.weapon_counts_as`，`stats.BLADE_TYPES`）。效果键 `no_firearms`、`blades_as_both`。
- 新的效果键：`companion_limit_bonus`、`extra_starting_companions`、`last_stand`、`no_basic_bleed_cure`、`bleed_damage`、`weight_reduction`；互斥用 `conflicts`。
- **每个 perk 只能选一次**。
- 已支持的 perk 效果键：`attribute_points`、`perk_points`、`no_companions`、`xp_percent`、`sight_bonus`、`hp_per_level`、`no_weapons`、`unarmed_attack`（替换空手攻击）；`instant_kill_percent`、`initiative_advantage` 已写进数据，等战斗流程接上。玩家的生命上限、经验倍率要用 `CharacterOptions.max_hp(character)` / `xp_multiplier(character)`，不要直接调 `stats.max_hp`。

### 变异（僵尸独有）
- 写在 `data/enemies.json` 的 `mutations`（名字、描述、效果），模板的 `mutations` 列表按 `chance`（%）随机带上（样品概率 10%，暂定）。**所有变异都算 buff，不改原始属性**。效果目前支持 `armor`（加护甲）、`attributes`（`{属性 id: 加值}`，作为 buff 挂上，资料卡显示“力量 9（5 + 某变异 4）”）。
- 现有变异（生成条件暂不管，只定效果；除表皮硬化外都要等战斗流程接上）：
  - **表皮硬化**：护甲 +4。
  - **尸爆**：生命降到 25% 以下时原地蓄力 1 回合（**蓄力期间被打死就不爆**），随后爆炸，半径 6 格内所有人类受到 体质×3 点**强酸**伤害（僵尸免疫）；可敏捷检定（难度 = 僵尸体质×1.5）减半，也可用盾牌格挡（格挡难度 = 僵尸体质×1.5 + 10，即比敏捷检定难 10 点）。
  - **酸蚀**：徒手攻击额外 1d4 强酸伤害，并叠 1 层强酸腐蚀（每层每回合 4 点、持续 3 回合、最多 5 层）。
  - **长舌**：长舌作为武器（射程 7 格、1d6、精准看体质、每次 9 行动点），被命中者力量检定（难度 = 僵尸体质×1.5），失败被拖到僵尸面前。
- 变异描述可以写 `{体质x3}`、`{体质检定}` 占位符，资料卡按这只僵尸的实际属性填数字（`enemies.mutation_text`）。
- 伤害类型新增**强酸**（`acid`），和火焰、流血一样不受护甲减免。测试：`敌人 行尸 精英 表皮硬化`（写了变异名就强制带上）。

### 敌人（框架已做，具体僵尸尚未设计）
- 模板写在 `data/enemies.json`（属性、等级、攻击 `{name, type, damage}`、护甲、描述），规则在 `enemies.py`，启动时检查数据。
- 敌人和玩家用同一套公式：生命、精准、闪避、先攻、行动点、力量伤害修正、暴击范围都一样。
- **僵尸的心智属性（智力、感知、魅力）固定为 1**（感知 1 会让闪避和先攻偏低）。
- 普通僵尸三种（原始属性，力量 / 敏捷 / 体质）：**行尸**（普通僵尸）5 / 5 / 5；**疾尸**（敏捷僵尸）6 / 7 / 4；**壮尸**（肥胖僵尸）6 / 4 / 7。心智属性（智力 / 感知 / 魅力）都是 1。这三种都是最基础僵尸的变体，在此之上再叠等级、变异、精英 / 首领强化。**最低生成等级**（模板的 `min_level`）：行尸 1，疾尸、壮尸 3；生成时等级不会低于它（`EnemyBook.create(level=)`）。测试：`敌人 疾尸 5级 精英`。
- **每个个体随机**（模板的 `loadout` → `loadouts` 随机表，概率暂定）：武器按权重抽，没武器就用抓挠——**僵尸的空手攻击（抓挠）视为轻刃**（1d6，暴击范围 19-20，精准看敏捷，吃力量修正）；每件护甲按概率独立判定；每条胳膊 / 腿按概率独立判定是否缺失。胳膊不够拿不了武器（双手武器要两条、单手要一条），两条都没了只能**撕咬**：轻刃、1d4、暴击 20，是**劣质武器**（`poor: true`）——精准只按属性 × 1 算（`stats.POOR_ACCURACY_MULTIPLIER`），不是 × 1.5。劣质标记对玩家的武器物品同样有效。**断腿的效果尚未设计**，目前只显示。武器、护甲直接引用 `world.json` 的物品。
- **等阶**（`stats.ENEMY_TIERS`）：普通不加成；**精英**力量、敏捷、体质 +2，生命上限再 +20；**首领** +4、+40。这些加成是 buff，不改原始属性（敌人的 `base_attributes` / `buffs`）。名字前加“精英”“首领”。
- 测试指令：`敌人 疾尸 精英` 随机生成一个看资料卡；`试攻击 壮尸 首领` 用自己的武器打一次（会扣它的生命）。“僵尸”“丧尸”是行尸的别名。

### 场景与走动（已实现）
- 每个地点都可以在 `data/world.json` 里写 `grid`：`tiles` 是 **10 行 × 16 列**的字符串数组（`#` 墙、`.` 地板、`~` 障碍物、`+` 门、`<` 上楼、`>` 下楼），`doors` 把出口方向映射到门 / 楼梯那一格的 `[x, y]`（键和该房间的 `exits` **完全一致**），`objects` 写物品 / NPC 的初始坐标。**没写 `grid` 的房间自动退回老做法（走一步 = 直接换房间）**，所以旧数据照样能跑。
- 坐标约定：`tiles[y][x]`，y=0 是最北那行、x=0 是最西那列；北 / 南门在第 0 / 第 9 行，西 / 东门在第 0 / 第 15 列。门 / 楼梯那一格要在边界上（`up` / `down` 不限）。
- **走动**：在有场景的房间里，`走 东` 这类指令 = 走一格；撞墙或障碍物既不移动也不消耗；走到门 / 楼梯那一格就换房间。换房间时人物落在目标房间「对面那扇门里面」的那一格（`Game.entry_tile`）。
- `走 上` / `走 下` 是楼梯：得站在楼梯格上或紧挨着它，否则提示楼梯在第几列第几行（`Game._take_stairs`）。**网页版移动栏不再放上下两个按钮**（改成点场景里的楼梯格走过去），控制台版照旧可以打 `走 上`。
- **拾取 / 说话要走到跟前**（`Game.near`：同一格或相邻一格，斜角也算）：不在跟前时 `拿` / `说话` 会提示东西在第几列第几行、让你先走过去；`查看` 不受限制，可以远程看。网页版点场景里的物品 / 人物方块，**「拿取」「说话」会自己先走过去再执行**（`doSceneAction` 先 `scenePath` + `walkAlong(steps, after)`，走完再发 `拿 X` / `说话 X`；已经在跟前就直接发指令），「走过去」那一项仍然保留（只移动、不拾取）。
- **消耗室内外一样**：每 10 步 1 点体力（`indoor_steps` 累加）、每格 1 点行动点，超重翻倍；时间按回合走（见“体力与时间”）。这句提示在 `Game._pay_move` 里生成，网页版和控制台版共用。
- 物品坐标：世界数据里写了的用写的，没写的（包括玩家丢下的）自动找最近的空格子。**地面物品是一件一格**：`Game.room_items[房间]` 是一串物品 id（**同一种东西地上可以摆好几件，id 会重复**），每件东西的格子记在 `Game.ground_positions[房间]`（一串 `[x, y]` 或 `None`，**和 room_items 一一对应，增删必须两边一起动**，读写走 `ground_positions_in` / `ground_names` / `ground_names_at`；老存档的 `item_positions`（按物品 id 记的字典）读档时由 `_load_room_items` 搬过来）。玩家自己的坐标存在存档的 `pos` 字段。NPC 位置是静态的，直接从 `grid.objects` 读。
- **随机物资**：地点可以写 `"random_items": [{"id": "canned_food", "min": 1, "max": 5}]`，**第一次走进这个地点**时掷一次个数（`Game.roll_room_spawns`，用 `self.dice.rng`），之后反复进出（包括读档回来）都不会再生成 —— 判定看 `visited`。便利店就是 1~5 个肉罐头。
- 网页版把当前房间打包成 `state.scene`（`width` / `height` / `tiles` / `doors` / `things` / `player`），视图栏照着画格子；点格子会按 BFS 找路一格一格走过去（`web/app.js` 的 `scenePath` / `walkAlong`），方向键也是走一格。

### 背包与装备（已实现）
- **装备着的东西不在背包里**：`Game.inventory` 只装没穿在身上的；`equipment` 和 `worn` 各自存物品 id（双手武器两个手槽存同一个 id）。负重按「背包 + 手上 + 身上」一起算（`Game.all_carried`），所以装备不会让你变轻。
- **背包是一格一堆**：`Game.inventory` 的每一项都是 `{"sid": 堆号, "id": 物品 id, "count": 几个, "auto": 能否被自动堆叠}`（`Game._new_stack`）。`sid` 从 1 往后发（`next_stack_id`，存进存档），界面靠它指定「这一堆」。读写背包一律走这几个方法，**不要直接 `self.inventory.append/remove`**：`add_item` / `take_item` / `count_item` / `inventory_ids` / `find_stack` / `merge_stacks`。
- **堆叠词条**：只有 `data/world.json` 里写了 `"stack": true` 的物品才摞得起来，一堆最多 `stats.STACK_MAX`（5）个；别的物品一格一件（`stats.stack_max`）。目前有堆叠词条的是肉罐头、矿泉水、急救包、能量棒、充电宝。写数字（例如 `"stack": 8`）可以单独放宽这一件的上限。
- **自动堆叠只在「物品进背包」那一刻判定**（拿起、脱下、装备换下来都算）：`add_item` 会先往已有的 `auto=True` 的堆里摞，摞满再开新堆。**手动拆出来的那一堆 `auto=False`**，以后捡到的东西不会摞进去，但可以手动拖到同种物品上合并（`merge_stacks`，目标堆满了就剩下不退）。界面里这种散堆左上角有个「散」标记。
- 相关指令：`拆分 <东西> [数量]`（不写数量就拆一半；拆出来的那堆不会自动堆叠）、`堆叠 <东西>`（把这种物品的几堆合并）、`堆叠 <堆号> <堆号>`（拖到另一堆上时界面发这个）、`放下 <东西> [数量]`（一次丢几个）。`拼` 的解析见 `Game._stack_arg`：第一段是纯数字就当堆号，否则按名字 / 别名找。
- 装备：`Game.cmd_equip` 把物品从背包拿走，被换下来的那件自动回背包；末尾可以写 `主手` / `副手` 指定拿到哪只手上（网页版拖到哪个方框就带哪个，例如 `装备 开山刀 副手`）。武器、盾牌这些手持物统一走 `Game._hold`。
- **手持物类别**（物品的 `hold`，`stats.HOLD_TYPES` / `hold_type` / `hold_slots`）：**单手**（主手、副手都能拿）、**双手**（只能拿在主手，强制占掉副手，副手原来的东西会被卸下）、**主手**（只能拿主手）、**副手**（只能拿副手）。**除非设计者明确声明，没有任何装备属于主手 / 副手类**；没写 `hold` 的武器、盾牌一律按单手。手上是双手物时，拿任何东西都会先把它整个放下。换手（`_switch_hand`）只对单手物有效，对面是主手 / 副手专用物时换不过去。现在：开山刀、军用匕首、手电筒是单手，撬棍是双手（代用，1d10 降一档 = 1d8），防暴盾牌是单手；目前没有主手 / 副手类物品。
- **换手不用先脱**：已经拿在手上的武器再 `装备 X 另一只手`，`Game._switch_hand` 会两只手直接对调（另一只手空着就挪过去）。双手武器和「对面拿的是盾牌 / 不是武器」的情况不换，会给出说明。
- 卸下：`Game.cmd_unequip` 把装备放回背包；**放回去会超过负重上限就丢在脚下**（当前房间的地上，并给它找个空格子），提示写在返回文字里（`Game.stow` / `Game._to_ground`）。换装时被换下来的那件同理。
- 手电筒是**武器**（`hold: one_hand`，`weapon: {type: blunt, damage: 1d4}`，和开山刀同一套装备逻辑）：可以拿在主手或副手，`装备 手电筒 副手` 也行。原来那个「照明」装备位已经删掉（`gear_slots` 里不再有 `light`），所以**带没带手电筒**才是关键：下地下停车场时 `requires: "flashlight"` 的判定看背包**和**身上（`Game._travel` 里查 `count_item` 或 `equipped_ids`），放背包里、拿在手上都算带着。旧存档里装在照明位上的手电筒，读档时 `_load_worn` 会**收回背包**（装备位没了，东西不能凭空消失）。
- 旧存档兼容：老存档里 `inventory` 是一串物品 id（一格一件），`_load_inventory` 会顺手搬成堆的格式（同种的重新摞起来、堆号重排）；老存档里装备同时也留在 `inventory` 里，读档时 `_load_equipment` / `_load_worn` 会把它从背包拿走，不会重复算；`_load_worn` 遇到**现在的世界数据里已经没有的装备位**（例如删掉的照明位）会把那件东西放回背包，而不是丢掉。
- 负重状态的中文说明用 `stats.load_label`：**轻载**（不超过上限的 30%）、**中载**（30~70%）、**重载**（70~100%）；超过上限仍然是原有的 `超重` / `严重超重`（会扣移动能力）。

### 界面
- 两个入口共用同一个 `engine.Game` 和同一个存档（`saves/save.json`）：`main.py` 是控制台版，`webui.py` 是网页按钮版。
- 界面不许自己实现游戏规则：网页版每个按钮都翻译成一句玩家指令交给 `Game.handle()`（点“东”＝`走 东`）。要加新玩法就在 `engine.py` 的指令表里加指令，两个界面同时受益。
- **网页版布局：六个固定区域，名字不许改**——**左侧栏**（`.side-left`，角色卡：等级 / 技能点 / 生命 / 体力 / 负重 / 状态 + 可折叠的属性、战斗、同伴。**「行动消耗 ×N」那一行已删**，力竭在状态区里显示）、**视图栏**（`.main.view-panel`，中间列上半：房间栏（带 **场景 / 背包** 两个页签）+ `#scene-body` 的 16×10 格子场景 + `#bag-panel` 背包面板，两者同时只显示一个；时钟在视图栏里——场景页签浮在画面左上角、背包页签在顶部那一行最右边，两个页签都看得见；颜色图例压在视图栏最下面一整条，点场景里的物品 / 人物方块弹小菜单走过去 / 拿取 / 查看 / 说话）、**移动栏**（`.move-panel`，中间列下半**正中间**，`#move-body` 四个方向（东 / 南 / 西 / 北）的九宫格，一个方向 = 走一格；**上下楼没有按钮，点场景里的楼梯格**）、**快捷区域1**（`#quick-zone-1`，**装备栏**：10 个方框（主手 / 副手 / 头 / 身体 / 腿 / 脚 / 饰品 1 / 饰品 2 / 披风 / 背包；照明位和手部已删），可以拖动装备 / 脱下 / 换手，见 `界面区域.md`）、**快捷区域2**（`#quick-zone-2`，**文字记录** `#log` + 指令输入 `#cmd-form`）、**右侧栏**（`.side-right`，只有 `#action-body`：背包快捷栏 / 休息 / 存档读档 / 系统——时钟、「这里」列表、「打开背包」按钮都已移走，开背包点视图栏右上角的「背包」页签；**拆分 / 堆叠不再放系统栏**，改成点背包里的物品出菜单，右侧栏的说明文字也精简过，目标是窗口不用滚动就能看全）。完整说明（含各区域现在多大、想改尺寸改哪一行）写在 **`界面区域.md`**，改界面先看它。
  结构上 `.layout` 是三列，中间 `.play-col` 两行（视图栏 `minmax(180px, 1fr)` + 下排 `var(--h-bottom)`），下排 `.bottom-row` 三列（快捷区域1 `1fr` | 移动栏 `var(--w-move)` | 快捷区域2 `1fr`，左右等宽所以移动栏自然居中）。宽度开关是 `style.css` `:root` 里的 `--w-left` / `--w-right` / `--w-move` / `--h-bottom`（下排固定高度）/ `--cell`（格子大小）。**`--cell` 是按视图栏真正能用的地方算出来的**（`--w-mid` = 中间列宽、`--h-scene` = 视图栏高减去房间栏与图例条），不是写死的 vw/vh 比例：改 `--w-left` / `--w-right` / `--h-bottom` 之后格子会自己跟着变。`--h-scene` 里那个常数（现在 139px）如果调小了，视图栏会冒出滚动条、地图也会被挤偏，改完要用无头浏览器量一次。
  **下排必须是固定高度**：以前是 `auto`，文字栏每多一条消息就把下排顶高一截，整页跟着长；现在 `.text-zone .log` 是 `flex: 1 1 0; height: 0`，消息只在文字栏内部滚动（灌 40 行实测下排高度不变、页面不出滚动条）。改这一块时别把 `--h-bottom` 去掉。
  **每个区域的根元素都带 `data-region="区域名"`**（例如 `data-region="视图栏"`），加新的块状界面时照这个写，以后靠 `data-region` 一条命令就能搜出整个区域。`renderChar()` → 左侧栏，`renderView()` → 视图栏（按页签分派给 `renderScene()` / `renderBag()`），`renderEquip()` → 快捷区域1（含拖放），`moveSection()` → 移动栏，`bagSection()/restSection()/saveSection()/systemSection()` → 右侧栏；请求中要一起禁用（见 `setBusy()`）。左侧栏的 属性 / 战斗 / 状态 是可折叠分区（`section()` + `collapsed`，收起状态存在 localStorage `fengcheng.collapsed`）。**下排三块（装备 / 移动 / 文字）的标题条统一成一样高**（`.bottom-row .panel-head`，padding `3px 8px`，标题 12px、图标 13px，实测三条都是 27px）；**注意选择器权重**：`.panel-head` / `.panel-head h3` 定义在后面，改标题条一定要写成 `.bottom-row .panel-head ...` 这种更具体的形式，否则同权重会被后面的规则盖掉（踩过这个坑：横幅一直是 46px 高、字也是 14px）。下排整体做扁：`.move-panel .dir` padding `4px`、图标 15px，实测下排 374px、视图栏 : 下排 ≈ 60 : 40。
- **物品 / 装备 / 人物 / 楼梯现在都是黑底白字的占位方块**（`.item-chip` / `.tile-chip` / `.bag-icon`），以后换成真图片只改 `style.css` 这几处和 `renderScene()` / `bagCell()` 里画方块的地方。
- **背包面板占视图栏**（`#bag-panel`，`renderBag()`）：顶部一行是件数 / 载重和**右侧的时钟**（`clockChip()`，和场景页签共用同一个函数），一屏 48 格分页（`BAG_PER_PAGE`，`[data-bag-page]` 翻页），每格是黑底白字的小方块（44px，比装备栏的方块小）+ 数量角标 `×n` + 散堆的「散」标记；**点格子才弹出菜单**（查看 / 使用 / 装备 / 拆分…（可堆叠且多于 1 个）/ 堆叠（背包里同种东西占了 ≥2 格）/ 登记到快捷栏 / 丢弃 1 个 / 丢弃全部 ×n，`itemMenu()` + `doBagAction()`，菜单挂在 `#bag-grid` 里跟着格子定位）。拖动＝装备（拖到快捷区域1 的方框）、拖到同种物品上＝合并、拖到右侧快捷栏＝登记。翻页状态在 `bagPage`、菜单在 `itemMenuSid`、拆分条在 `splitSid`（都只是前端状态，刷新就回到第 1 页）。
- **场景里点方块出小菜单**（`thingMenu()` / `placeThingMenu()` / `doSceneAction()`，状态在 `thingMenuId`）：物品给「走过去 / 拿取 / 查看」、人物给「走过去 / 说话 / 查看」，翻译成 `拿 X` / `说话 X` / `查看 X`；**拿取 / 说话会自动走过去**（先 BFS 找路 `walkAlong(steps, after)`，走到那一格再发指令；已经在跟前就直接发），**「走过去」只移动、不拾取**（已经站在那一格上时不显示这一项）；点击格子里有东西的格子**不走路**（先出菜单），点别的空格子先收菜单。人和东西挤在同一格时那一格写东西的名字、小字写「我在这里」（`放下` 就是丢在自己脚下，不这么画就会看不见）。舞台数据来自 `engine.scene_state()` 的 `things`（带 `id` / `name` / `kind`；地面物品的 `id` 是 `g` + 序号，因为同一种东西可能有好几件）。
- **右侧行动面板里的三块约定**（现在只剩这三块：背包快捷栏 / 休息 / 存档读档，加上系统）：**背包快捷栏固定 3 格、只能手动登记**（把背包里的东西拖到格子上，或菜单里的「登记到快捷栏」；格子里点 ✕ 取下。登记表存 localStorage `fengcheng.quick`，格式是 `[{id,name} | null × 3]`，老格式（一串 id）读进来也能用）。点一下＝使用 / 装备 / 查看，命令由 `webui.Session.quick_action` 决定；**登记的物品不在背包里时格子写「没带」**，不会自动拿背包里的东西来填。休息是滑条（1~480 分钟）+ 快捷档位；存档是「动作 + 槽位」两排按钮，先点存档 / 读档 / 清空（选中变绿），再点 1 / 2 / 3 执行。主菜单才显示完整存档描述。**右侧栏的说明文字只留最短的一句（存档那块的「当前槽：N 号」、休息满体力时的一句提醒），间距由 `style.css` 末尾的 `.side-right` 一段收紧**。
- 浮层（`#modal`）按 `modalKind` 分派：`skills`（技能树）、`confirm`（二次确认）。**背包不再是浮层**，它占视图栏；加新浮层就在 `renderModal()` 里加一个分支。
- **关掉网页 = 关掉游戏**（服务端在 `webui.py` 的「页面存活探测」一段，前端在 `web/app.js` 的 `PAGE_ID` / `sayGoodbye()`）：每次打开页面生成一个随机 `PAGE_ID`，心跳和每条 POST 都带着它（`Session.pages` 是 `页面 id -> 最后活动时间`）；页面临走前（`pagehide`）用 `navigator.sendBeacon('/api/bye')` 报一声，`page_closed()` 只摘掉自己那一个 id —— **开两个页面时关掉一个不会结束另一个**。一个 id 都不剩时点上一个 `CLOSE_GRACE_SECONDS`(12 秒) 的倒计时，宽限期内有页面回来（刷新就是这么回事）就撤销；到点了 `shutdown_because_page_closed()` 结束这一局（`started=False` / `running=False`）并调 `Session.on_close`（`main()` 接的是 `server.shutdown`）把服务停掉，`main()` 返回 `EXIT_PAGE_CLOSED`(2)，`启动网页版.bat` 看到 2（或「已经在跑」的 3）就直接关窗口。**全程不碰存档**。三个阈值管的不是一回事，别混：`PAGE_TIMEOUT`(150 秒没心跳就不算「有人在看」，`ping.pages` 会减掉 → 重新双击一定帮你开浏览器)、`GAME_IDLE_TIMEOUT`(1800 秒一个页面都没有才真的结束这一局：浏览器被强杀 / 电脑休眠这种来不及报备的情况，游戏先留在内存里等玩家回来，重新双击接着玩)、`CLOSE_GRACE_SECONDS`(12 秒，页面打过招呼之后的收尾)。看门狗 `_watch_loop()` 每 `SWEEP_SECONDS`(10 秒) 扫一次；**从来没有页面连上来过的服务不会被误关**（`ever_had_page`，否则刚起来的服务会把自己关掉）。
- **退出游戏按钮**：`POST /api/quit` 同样会结束这一局并停掉本地服务（`closed=True`，`main()` 返回 2），前端切到结束页。浏览器不允许脚本关闭不是它自己打开的标签页，所以结束页上的“关闭此页面”只是尽力而为，关不掉要给出提示。页面这边心跳连丢 3 次（服务已经没了）也会切到结束页并给出提示。
- **同一个地址只跑一个服务**：`webui.main()` 先判断端口空不空（`port_is_free()`，**必须用不带 `SO_REUSEADDR` 的裸 socket**，因为 Windows 上带这个选项的 bind 在别人已监听时也会成功），空就直接起服务、一点探测都不做；端口被占时才 `probe_app()` 问一句 `/api/ping`（超时 0.3 秒，绕开系统代理），是本游戏就复用并退出（返回 `EXIT_ALREADY_RUNNING`(3)）。`/api/ping` 里带 `pages`（现在几个页面在看）和 `idle_seconds`：**`pages > 0` 才可能说明页面真的还开着**，这时才不重开标签页（`--open` 强制、`--force` 另起一个），否则一定帮你打开 —— 「明明页面已经关了却说还开着」就是以前只看 `idle_seconds` 造成的。心跳（`POST /api/heartbeat`，20 秒一次）是 `pages` 的主要来源，其余每个 POST 也会记一笔，所以页面刚打开、还没走到第一次心跳时也认得出来。`Session` 是 `LazySession` 懒加载的，收到第一个请求才建（`set_on_close()` 先把停服务的回调存着，建的时候再交给 `Session`）。
  **启动耗时很敏感**：改成这样之前，对每个空闲端口做 HTTP 探测会一直等到超时（本机上 SYN 被丢掉，不会立刻 ConnectionRefused），10 个端口 = 10 秒；现在正常启动 ≈ 0.25 秒，只有端口被占时才会多花 0.3 秒。
- 角色创建复用 `CharacterCreator` + `Prompter`：`webui.py` 里的 `WebPrompter` 只把 `input()` / `print()` 接到 HTTP 上，属性、背景、同伴的校验逻辑仍然只有一份。
- 图标是手写的 SVG 精灵 `web/icons.svg`，单色、全部用 `currentColor`；新增图标后要把名字加进 `web/app.js` 的 `USED_ICONS`。
- 只用标准库，只监听 `127.0.0.1`，不用外部 CDN 或图片素材。
- 体力、时间、休息、异常状态这些规则全在 `stats.py` 和 `engine.py` 里，界面只负责显示和发指令（例如“休息 30”“走 东”）。走不通、体力不够这类失败提示，服务器会在响应里附一个 `notice` 字段，界面用它弹浮层。

### 存档与物品使用
- 存档分 **3 个槽位**：`saves/save1.json` ~ `save3.json`。指令是 `存档 2` / `读档 2` / `清空 2`；不写槽位就用当前槽（读档时若当前槽是空的，就读最近改过的那一个）。老版本的单存档 `save.json` 会在启动时自动复制成 `save1.json`（原文件保留，不删），复制完写一个 `saves/.migrated` 标记——**有这个标记就不会再搬**，否则玩家清空 1 号槽之后，下次启动又会被旧文件顶回来。
- 存档写盘走 `engine.write_json_file()`：先写 `.tmp` 再 `os.replace`，写坏了也不会把原来那份存档毁掉；`cmd_save` **写成功之后才切换当前槽**。
- 存档里的 `inventory` 现在是**一格一堆**：`[{"sid":1,"id":"water","count":3,"auto":true}, ...]`，另外带一个 `next_stack_id`。老存档（一串物品 id）读进来会由 `_load_inventory` 自动搬成新格式；`count` 超过当前堆叠上限的还会被拆成几堆。
- 物品的使用效果写在 `data/world.json` 里物品的 `use` 字段，规则在 `items.py`：

  ```json
  "use": {
    "consume": true,
    "message": "使用时先显示的一句话",
    "effects": [
      {"type": "stamina", "ratio": 0.5},
      {"type": "hp", "amount": 30},
      {"type": "cure", "condition": "bleeding"}
    ]
  }
  ```

  `ratio` 按上限比例算、`amount` 按固定点数算；`consume` 默认 `true`（用掉即消耗）。目前写了效果的是能量棒（食物 +10、体力 +25%）、肉罐头（食物 +30、生命 +1）、矿泉水（水源 +30），**其它物品只要加上 `use` 字段，指令和界面上的“使用”按钮就会自动出现，不用改代码**。要加新的效果类型，在 `items.py` 的 `EFFECTS` 里注册一个函数即可。生命值满了照样能用肉罐头，只是不会超过上限（`_effect_hp` 里 `min(cap, ...)`）。
- **食物标签**：`"tags": ["food"]` 就是带食物标签（`items.is_food`），目前肉罐头、矿泉水、能量棒都有。
  - **食物与水源**（`character.food` / `water`，上限 `stats.NEED_MAX` = 100，满值开局）：随时间下降——食物每 30 分钟 −1（每小时 −2）、水源每 15 分钟 −1（每小时 −4），`Game._drain_needs` 在 `advance_time` 里扣。降到 **50% / 30% / 10%** 及以下分别进入：**有点饿 / 有点渴**（体力消耗 +25%）、**饥饿 / 口渴**（体力消耗 +50%）、**饿死了！/ 渴死了！**（体力消耗 +50%，并且**每回合生命 −1**）。饥饿和口渴的倍率相乘；体力消耗带小数时攒在 `Game.stamina_carry` 里，满 1 才扣。状态实时算出来（`Game._need_condition`），不进存档；跨过等级时在指令输出后面补一句提示（`pending_notes`）。回复：肉罐头 食物 +30、生命 +1；矿泉水 水源 +30；能量棒 食物 +10、体力 +25%（物品效果类型 `food` / `water`）。**原来“累计消耗 60 点体力就口渴”的规则已经去掉**，口渴完全由水源条决定。
  - 存档里对应的字段：角色的 `food` / `water`，以及 `need_minutes`、`stamina_carry`、`food_uses`（最近几次进食时间）；老存档没有就按满值 / 0 / 空处理。
- 体力不足造成的力竭清不掉（`Game.clear_condition` 会说明原因），所以 `{"type": "cure", "condition": "exhausted"}` 对它是无效的，得用恢复体力的效果。
