# 封城第七天：项目说明

现代丧尸末世背景的中文文字冒险游戏，开放世界，角色构筑参考 CRPG（辐射式属性 + 技能树）。
两人合作开发，通过 GitHub 同步。运行方式和文件结构见 README.md。

## 开发约定

- **必须兼容 Python 3.9**：macOS 自带的 `/usr/bin/python3` 是 3.9.6。不要用 3.10+ 的写法（`X | None` 类型标注、`match` 语句等），改完用 `/usr/bin/python3 main.py` 测试。
- 不引入第三方库，只用标准库。
- **内容放数据，规则放代码**：地点、物品、NPC、背景、技能、姿态都写在 `data/*.json`；公式集中在 `stats.py`。
- 玩家看到的文字全部用中文；中文指令允许不加空格（如 `拿手电筒`），英文别名要用空格隔开。
- 存档（`saves/`）不进 Git。改存档格式时要兼容旧存档（参考 `Game.cmd_load` 和 `Character.from_dict` 的做法）。
- 技能数据在启动时会做引用检查（`SkillTrees._validate`），新增引用类字段时一并加检查。

- **所有数值计算一律向下取整**（伤害、闪避、检定修正、体力消耗与恢复、经验、物品效果、负重小数位等）。带小数倍率的先用 `Fraction` / `Decimal` 精确算再取整，避免浮点误差。

## 已确定的设计

### 角色创建
名字、性别（可自定义）、年龄、身高、样貌（自由填写）、背景（从选项中选）、属性分配、同伴（不带 / 预设 / 自定义）。

### 属性（创建时 3~10，5 为普通人）
力量、敏捷、体质、智力、感知、魅力。创建时每项默认 5、下限 3、上限 10，共 33 点可重新分配。
**上限 10 只约束创建角色时的分配**：后期属性成长可以超过 10，体力消耗减免这类公式按超过 10 也成立。
衍生数值：负重、近战伤害、钝器精准（力量）；行动点、锐器精准、闪避、先攻（敏捷）；生命值、生命恢复、武术精准（体质）；经验倍率、每级技能点（智力）；枪械精准、闪避、先攻（感知）；同伴上限（魅力）。
- **生命值上限** = 10 +（体质 ÷ 2）× 等级（`stats.max_hp`）；升级时生命回满。
- **生命恢复**：战斗外每 10 回合恢复 体质 ÷ 2（向下取整）点生命（`stats.hp_regen`）；移动和 `等待` 都算回合。
- **同伴上限**：魅力每比 3 多 2 点多带 1 个同伴（3 → 0、5 → 1、7 → 2、9 → 3），`stats.companion_limit`。
- 所有属性在检定时的修正值 = 属性值 × 1.5（见“抛骰”）。

**属性部分的公式暂未最终确定**，计划等其他系统设计完后统一回头检查。

### 体力与时间（已实现）
- 体力上限 = 10 ×（体质 + 力量）：各 5 时 100，各 3 时 60（下限），各 10 时 200。属性超过 10 同样照算。
- 行动消耗倍率只看敏捷：5 是基准；低于 5 时每点 +5%（3 点 → +10%）；高于 5 时每满 5 点 −10%（7 点不减、10 点 −10%）；最低降到 50%。
- 走路消耗：建筑物内每 10 步 1 点体力（`Game.indoor_steps` 计数，存进存档）、每步 1 分钟；建筑物外每步 1 点、5 分钟（房间在 `data/world.json` 里用 `outdoor` 标记）。体力不够就走不动。
- 体力归零当场休克：失去行动能力，强制休息到上限的 30% 才醒，时间照常流逝。
- 体力低于上限 10% 进入力竭：攻击力 −50%，体力恢复后自动解除。**清除异常状态的道具清不掉这种力竭**，必须恢复体力；其它来源的力竭可以用 `Game.clear_condition("exhausted")` 清。
- 休息：每半小时恢复 10% 上限，**一次可以休息 1 分钟 ~ 8 小时**（`engine.REST_MINUTES_MIN` / `REST_MINUTES_MAX`，8 小时一定够补满任何角色的体力）。**体力满了不阻止休息，只是体力不再涨、时间照走**（以前的实现是体力一满就提前结束，会把想靠休息推进时间的玩家卡住）。控制台写 `休息 90` / `休息 2小时`，网页上是滑条 + 快捷档位。
- 计时器从第七天 14:00 开始，显示“第 N 天 HH:MM”，跨过午夜进入下一天。**只有移动和休息推进时间**，其它指令既不耗时也不耗体力。
- 走不通时的提示按房间数据来：房间的 `blocked` 写“墙壁”（室内）或“障碍物”（走廊、室外）。出口可以写 `danger`（一句描述），网页版会把这个方向标红。
- **每一步移动花掉多少体力写在正文里**：`cmd_go` 成功后往房间描述后面追加一句 `（移动消耗 N 点体力：旧 → 新/上限，用时 X 分钟）`（用 `format_duration` 写时长）。走不通、体力不够这两种情况不消耗体力，所以不加这句。写在引擎里是为了让网页版和控制台版共用同一句话。

### 技能树
- 花技能点解锁技能；初级技能 1 点，高级技能可能更贵。
- 初始技能点暂定 4（`starting_skill_points`），每级技能点公式暂定，都要等技能树设计完再定。
- **技能效果受所属技能树对应的属性影响。**
- 每棵树至少两条分支，分支只是侧重不同，不限制玩家混着学。
- **所有技能在没有特别声明的情况下，一律视为用主手武器发动。**
- 技能数据可以写 `ap_cost`（使用 / 激活本身的行动点）和 `cooldown`（冷却回合数），技能树界面会显示。
- **冷却 N 回合 = 使用那一回合之后再等 N 回合**：冷却 1 就是第 1 回合用、第 2 回合冷却、第 3 回合可以再用。
- 技能树：锐器（敏捷）、钝器（力量）、枪械（感知）、武术（体质）、潜行（敏捷）、生存（体质）、搜刮（感知）、交涉（魅力）、医疗（智力）、制造（智力）、武器掌握、灵能（特殊）。
- **武器掌握**：为不同的持握方式提供增益，分支是单手（一只手拿单手武器、另一只手空着）、双持、双手、持盾。**武器持握类的技能都放在这里**，不放进锐器、钝器等武器类技能树。对应哪项属性尚未确定（目前不对应属性）。当前持握方式用 `Game.grip_style()` 判断（徒手 / 单手 / 双持 / 双手；持盾等盾牌做出来后再加）。
- **灵能无法觉醒**，只有创建角色时选择"灵能者"背景才能解锁。
- 目前每个分支只先设计一两个技能来展示风格：
  - 锐器·长刃（主题：姿态）：长刃姿态（进攻 / 防守 / 决斗，同时只能开一个，手持至少一把长刃即可，支持双持，切换不占行动）；随势斩（无姿态时为普通斩击，各姿态有不同额外效果）
  - 锐器·短刃（主题：流血与弱点）：放血
  - 随势斩、放血的伤害、距离、护甲无视、流血数值已按暂定公式写进技能描述（标了“暂定”），等战斗系统定下武器伤害、护甲、距离单位、行动点后再统一调整；技能的行动点消耗尚未定。
  - 技能树界面会自动列出技能提供的姿态及其数值（公式 + 按当前属性算出的结果），见 `stances.describe_granted`。
  - 武器掌握·单手：精通重击（被动，单手持用时暴击范围翻倍，18-20 → 15-20）、透甲（被动，单手持用时无视 5 点护甲）
  - 武器掌握·双持：连击（被动，双持时主手攻击后可用副手追击一次，行动点减半，`Game.offhand_attack_cost`）；双刃合击（主动，激活后下一次攻击 / 技能由两把武器同时发起，另一把强制视为技能对应的武器类型并应用技能效果）。**两者都要等战斗回合流程做出来才真正生效**；连击：主手攻击包括普通攻击和技能，但追击只能是普通攻击。双刃合击：激活消耗 3 行动点（技能数据的 `ap_cost`），冷却 1 回合；这一击不触发连击、也不算副手出手；同时攻击的行动点 = 该攻击 / 技能本身的消耗；两把武器分别掷命中和伤害；激活后保留到下一次攻击、不能叠加、脱战清除。
  - 武器掌握·持盾：双重格挡（被动，持盾时每回合格挡次数 1 → 2）；盾击（主动，3 行动点、冷却 1 回合，1d4 伤害，目标体质检定失败则下回合最后行动；**检定难度、伤害是否吃力量修正尚未定**，实际效果等战斗流程做出来后接上）。
- **盾牌**：物品带 `shield` 字段（内容可以为空）就是盾牌，固定拿在副手；拿盾时持握方式为“持盾”（`grip_style` 返回 `shield`）。换双手武器会收起盾牌，反之亦然。目前样品：一楼大堂的防暴盾牌。
- **格挡**：持盾时每回合默认可格挡 1 次（`stats.BLOCKS_PER_TURN`）。敌人即将命中时自动进行格挡检定：d20 + 格挡修正，**敌方这次的命中（d20 + 精准）小于它就挡住**，攻击无效；掷出 20 必定挡住、1 必定挡不住。格挡修正 =（力量÷2 + 感知÷2）× 1.5，每步向下取整（`stats.block_modifier`、`dice.Dice.block`）。测试指令：`试受击 壮尸 精英`（敌人打你一次，不扣血）。
  - **被动技能效果**写在技能的 `effects` 里（类型见 `stats.PASSIVE_EFFECTS`，可以用 `grip` 限定持握方式），引擎用 `Game.passive_effects(类型)` 取当前生效的效果；新增效果类型要在 `stats.PASSIVE_EFFECTS` 登记并在引擎里接上
  - 交涉分支：说服、威吓；钝器的分支原本是持盾、双手，已移到武器掌握，钝器的新分支尚未设计
- 除锐器外，其他树里的"入门 / 进阶"都是**占位技能**，等设计后替换。

### 战斗系统（基础数值已定，回合流程尚未实现）
公式和常量都在 `stats.py` 的“战斗”一节，命中判定在 `dice.Dice.attack`。
- **所有掷骰都用 d20**（战斗和检定）。
- **命中**：d20 + 精准 **≥** 闪避 即命中（等于也算，和检定统一）；掷出 20 必中，掷出 1 必不中。
- **精准** = 所用武器对应的属性值：锐器（长刃 / 短刃）看敏捷、钝器看力量、枪械看感知、武术（徒手）看体质（`stats.WEAPON_ATTRIBUTES`）。没拿武器按徒手算。双持时每只手分别算。
- **闪避** =（敏捷 + 感知）× 1.5，向下取整（例如 16.5 → 16）。
- **先攻** = 敏捷 + 感知。
- **行动点**：每回合获得 敏捷 × 2；移动、使用技能、使用物品都消耗行动点；没用完的留到下回合，上限为每回合获得量的 2 倍；只在战斗中存在，不能带进战斗。开战第一回合就获得行动点。
- **普通攻击**消耗 6 行动点。
- **等待**：战斗中使用 = 结束当前回合，没用完的行动点保留（受 2 倍上限约束）；战斗外 = 原地等一回合（1 分钟，计入生命恢复）。战斗中的部分等战斗流程做出来后接上。
- **行动点消耗**：普通攻击 6、移动 1 格 1、使用物品（例如用绷带包扎）3（`stats.ATTACK_AP_COST` / `MOVE_AP_COST` / `USE_ITEM_AP_COST`）。
- **武器伤害骰**写在 `data/world.json` 物品的 `weapon.damage`：单手武器 1d8（开山刀、锤子、撬棍），双手武器 2d6（消防斧、大锤），短刃 1d6（短剑、匕首）。启动时会检查格式。徒手伤害 1d4（`stats.UNARMED_DAMAGE`）。
- **伤害计算**（`stats.final_damage`）：骰出的伤害 × 各来源修正（**相乘**，例如力量 +20% 和进攻姿态 +20% 是 ×1.2×1.2）×（暴击时 1.5），**向下取整**，再减护甲，**最低 0**。修正来源：力量（仅近战）、姿态（仅姿态要求的武器）、力竭 −50%。用 `Fraction` 计算，避免浮点误差影响取整。
- **暴击**：命中且 d20 点数落在武器的暴击范围内时，再掷一次命中判定确认：也命中就是暴击，伤害额外 +50%（在其他修正之后、护甲之前结算）；没命中就按普通命中处理（`dice.Dice.attack`）。掷出 20 只保证命中，是否暴击仍由第二次决定。
- **暴击范围**按武器类型（`stats.CRIT_RANGES`）：钝器和徒手 20；寻常锐器（开山刀等，长刃和短刃都算）19-20；宽暴击范围的锐器（弯刀、反曲刀、军用匕首）18-20，基础伤害 1d6——这类武器在 `world.json` 里单独写 `"crit_range": "18-20"`、`"damage": "1d6"` 覆盖默认值。**枪械的全部设计暂缓。**
- **护甲**提供固定减伤：身上所有部位的护甲值相加，每次受到的伤害减去这个总值。
  - 物品写 `"armor": {"slot": "head", "class": "light", "value": 2}`，用 `装备` / `卸下` 穿脱，每个部位一件，穿新的会自动换下旧的。
  - 护甲部位固定 5 个：头部、身体、手部、腿部、脚部（`world.json` 的 `armor_slots`）。
- **其他穿戴位**（`world.json` 的 `gear_slots`，不提供护甲）：饰品 2 个、披风 / 斗篷 1 个、背包 1 个。物品写 `"gear": {"slot": "accessory"}`（或 `cloak`、`backpack`），同样用 `装备` / `卸下`；饰品先放空位，两个都满了换下第一个。
  - **背包减重**：背包写 `"weight_reduction": 20`（%），背着时背包里所有东西（包括背包自己）的总重按这个比例打折（`Game._carried_weight`），负重上限不变。
  - 饰品、披风目前没有任何效果，具体效果和各种背包的减重率尚未设计；游戏里还没有这类物品。
- **超重**（`stats.load_level`，按打折后的背包总重算）：超过负重上限 → 超重，移动能力减半（战斗中每格 2 行动点）；超过上限 2 倍 → 严重超重，完全无法移动（`走` 会被拦下）。正好等于上限 / 正好 2 倍都不算。
  - 超重也能继续拿东西，拿、放、换背包、卸背包后负重状态变了会补一句提示；超重和严重超重会出现在异常状态里（实时计算，不进存档）。
  - 战斗外超重：走路（以及以后的大地图移动）的体力消耗和时间都翻倍（`stats.OVERWEIGHT_TRAVEL_MULTIPLIER`）。
  - 类别（`stats.ARMOR_CLASSES`，启动时检查数值范围）：寻常服装 0；轻甲 1~3，按部位定（胸甲 3、鞋子 1）；重甲 2~6，会降低每回合行动点（每件写 `ap_penalty`，相加后从 敏捷×2 里扣，上限随之变化）。**重甲每件扣多少行动点尚未确定**，目前游戏里没有重甲。
  - 目前只有一件样品：地下停车场的摩托车头盔（轻甲，头部，2）。
- **力量伤害修正**：力量每比 5 多 1 点，伤害 +10%；每少 1 点 −10%（力量 3 为 −20%）。适用于所有近战武器（锐器、钝器、武术），**不适用于枪械**（`stats.melee_damage_bonus`）。
- 长刃姿态的加成是**固定值，不随属性变化**：进攻 近战伤害 +20%、防守 闪避 +3、决斗 精准 +2。
- 姿态加成里的 `accuracy` 只加在姿态要求的那类武器上（决斗姿态只加长刃的精准），`dodge` 直接加闪避。
- 测试用指令：`试攻击 <闪避> <护甲>` 用手上的第一件武器试一次攻击，显示命中和伤害的完整计算过程（还没有敌人）。
- **距离与位置**：近战范围、后撤；移动能力受敏捷和穿戴装备影响。
- 借机攻击、护甲（及无视部分护甲）、缴械、持续状态（如流血：每回合掉血，持续 3 回合）。
- 其余数值（重甲的行动点惩罚、各部位护甲值、距离单位、技能的行动点消耗、护甲无视比例、流血伤害等）尚未确定，实现时先询问，不要自行编造。

### 敌人（框架已做，具体僵尸尚未设计）
- 模板写在 `data/enemies.json`（属性、等级、攻击 `{name, type, damage}`、护甲、描述），规则在 `enemies.py`，启动时检查数据。
- 敌人和玩家用同一套公式：生命、精准、闪避、先攻、行动点、力量伤害修正、暴击范围都一样。
- **僵尸的心智属性（智力、感知、魅力）固定为 1**（感知 1 会让闪避和先攻偏低）。
- 普通僵尸目前三种（属性暂定）：行尸（力 5 敏 5 体 5）、疾尸（高敏捷低体质：力 5 敏 7 体 3）、壮尸（高体质低敏捷：力 5 敏 3 体 7）。
- **每个个体随机**（模板的 `loadout` → `loadouts` 随机表，概率暂定）：武器按权重抽，没武器就按徒手 1d4；每件护甲按概率独立判定；每条胳膊 / 腿按概率独立判定是否缺失。胳膊不够拿不了武器（双手武器要两条、单手要一条），两条都没了攻击叫“撕咬”。**断腿的效果尚未设计**，目前只显示。武器、护甲直接引用 `world.json` 的物品。
- **等阶**（`stats.ENEMY_TIERS`）：普通不加成；**精英**力量、敏捷、体质 +3，生命上限再 +20；**首领** +6、+40。加成可以把属性推到 10 以上。名字前加“精英”“首领”。
- 测试指令：`敌人 疾尸 精英` 随机生成一个看资料卡；`试攻击 壮尸 首领` 用自己的武器打一次（会扣它的生命）。“僵尸”“丧尸”是行尸的别名。

### 界面
- 两个入口共用同一个 `engine.Game` 和同一个存档（`saves/save.json`）：`main.py` 是控制台版，`webui.py` 是网页按钮版。
- 界面不许自己实现游戏规则：网页版每个按钮都翻译成一句玩家指令交给 `Game.handle()`（点“东”＝`走 东`）。要加新玩法就在 `engine.py` 的指令表里加指令，两个界面同时受益。
- **网页版布局：六个固定区域，名字不许改**——**左侧栏**（`.side-left`，角色卡）、**文字栏**（`.main`，中间列上半：房间栏 + `#log` + 指令输入）、**移动栏**（`.move-panel`，中间列下半**正中间**，`#move-body` 六向九宫格）、**快捷区域1** / **快捷区域2**（`.quick-zone`，移动栏左右两块预留位，暂时留空、两块一样宽、跟移动栏一样高）、**右侧栏**（`.side-right`，顶部紧凑时钟 + `#action-body`：这里 / 背包快捷栏 / 休息 / 存档读档 / 系统）。完整说明（含各区域现在多大、想改尺寸改哪一行）写在 **`界面区域.md`**，改界面先看它。
  结构上 `.layout` 是三列，中间 `.play-col` 两行（文字栏 `minmax(180px, 1fr)` + 下排 `auto`），下排 `.bottom-row` 三列（快捷区域1 `1fr` | 移动栏 `var(--w-move)` | 快捷区域2 `1fr`，左右等宽所以移动栏自然居中）。宽度开关是 `style.css` `:root` 里的 `--w-left` / `--w-right` / `--w-move`。文字栏 : 下排 ≈ 68 : 32。
  **每个区域的根元素都带 `data-region="区域名"`**（例如 `data-region="移动栏"`），加新的块状界面时照这个写，以后靠 `data-region` 一条命令就能搜出整个区域。`renderActions()` 拆成 `moveSection()`（→ `#move-body` = 移动栏）和 `hereSection()/bagSection()/restSection()/saveSection()/systemSection()`（→ `#action-body` = 右侧栏），请求中要两块一起禁用（见 `setBusy()`）。时钟刻意做小（字号 14.5px、padding 7px）以省纵向空间；移动栏那条横幅也比别的面板头矮一截、窄一条（`.move-panel .move-head`，padding `3px 8px`，整条 27px 高，“移动”12px），不再横跨整个中间列。**注意选择器权重**：`.panel-head` / `.panel-head h3` 定义在后面，改移动栏横幅时必须写成 `.move-panel .move-head ...` 这种更具体的形式，否则同权重会被后面的规则盖掉（踩过这个坑：横幅一直是 46px 高、字也是 14px）。下排整体做扁：`.move-panel .dir` padding `4px`、图标 15px，实测下排 259px、文字栏 : 下排 ≈ 70 : 30。
- **右侧行动面板里的三块约定**：背包只留 3 格快捷栏（点一下＝使用 / 装备 / 查看，命令由 `webui.Session.quick_action` 决定；完整列表和 ★ 钉选在背包浮层里）；休息是滑条（1~480 分钟）+ 快捷档位；存档是「动作 + 槽位」两排按钮，先点存档 / 读档 / 清空（选中变绿），再点 1 / 2 / 3 执行。主菜单才显示完整存档描述。
- 浮层（`#modal`）按 `modalKind` 分派：`skills`（技能树）、`bag`（背包）、`confirm`（二次确认）。加新浮层就在 `renderModal()` 里加一个分支。
- **退出游戏按钮必须真的结束游戏**：`POST /api/quit` 会把 `Game.running` 置否并停掉本地服务，前端切到结束页。浏览器不允许脚本关闭不是它自己打开的标签页，所以结束页上的“关闭此页面”只是尽力而为，关不掉要给出提示。
- **同一个地址只跑一个服务**：`webui.main()` 先判断端口空不空（`port_is_free()`，**必须用不带 `SO_REUSEADDR` 的裸 socket**，因为 Windows 上带这个选项的 bind 在别人已监听时也会成功），空就直接起服务、一点探测都不做；端口被占时才 `probe_app()` 问一句 `/api/ping`（超时 0.3 秒，绕开系统代理），是本游戏就复用并退出。页面还有心跳（`POST /api/heartbeat`，20 秒一次）时不重开标签页（`--open` 强制、`--force` 另起一个）。`Session` 是 `LazySession` 懒加载的，收到第一个请求才建。
  **启动耗时很敏感**：改成这样之前，对每个空闲端口做 HTTP 探测会一直等到超时（本机上 SYN 被丢掉，不会立刻 ConnectionRefused），10 个端口 = 10 秒；现在正常启动 ≈ 0.25 秒，只有端口被占时才会多花 0.3 秒。
- 角色创建复用 `CharacterCreator` + `Prompter`：`webui.py` 里的 `WebPrompter` 只把 `input()` / `print()` 接到 HTTP 上，属性、背景、同伴的校验逻辑仍然只有一份。
- 图标是手写的 SVG 精灵 `web/icons.svg`，单色、全部用 `currentColor`；新增图标后要把名字加进 `web/app.js` 的 `USED_ICONS`。
- 只用标准库，只监听 `127.0.0.1`，不用外部 CDN 或图片素材。
- 体力、时间、休息、异常状态这些规则全在 `stats.py` 和 `engine.py` 里，界面只负责显示和发指令（例如“休息 30”“走 东”）。走不通、体力不够这类失败提示，服务器会在响应里附一个 `notice` 字段，界面用它弹浮层。

### 存档与物品使用
- 存档分 **3 个槽位**：`saves/save1.json` ~ `save3.json`。指令是 `存档 2` / `读档 2` / `清空 2`；不写槽位就用当前槽（读档时若当前槽是空的，就读最近改过的那一个）。老版本的单存档 `save.json` 会在启动时自动复制成 `save1.json`（原文件保留，不删），复制完写一个 `saves/.migrated` 标记——**有这个标记就不会再搬**，否则玩家清空 1 号槽之后，下次启动又会被旧文件顶回来。
- 存档写盘走 `engine.write_json_file()`：先写 `.tmp` 再 `os.replace`，写坏了也不会把原来那份存档毁掉；`cmd_save` **写成功之后才切换当前槽**。
- 物品的使用效果写在 `data/world.json` 里物品的 `use` 字段，规则在 `items.py`：

  ```json
  "use": {
    "consume": true,
    "message": "使用时先显示的一句话",
    "effects": [
      {"type": "stamina", "ratio": 0.5},
      {"type": "hp", "amount": 30},
      {"type": "cure", "condition": "bleeding"}
    ]
  }
  ```

  `ratio` 按上限比例算、`amount` 按固定点数算；`consume` 默认 `true`（用掉即消耗）。目前只有能量棒写了效果（恢复 50% 体力上限），**其它物品只要加上 `use` 字段，指令和界面上的“使用”按钮就会自动出现，不用改代码**。要加新的效果类型，在 `items.py` 的 `EFFECTS` 里注册一个函数即可。
- 体力不足造成的力竭清不掉（`Game.clear_condition` 会说明原因），所以 `{"type": "cure", "condition": "exhausted"}` 对它是无效的，得用恢复体力的效果。
