# 界面区域命名

网页版的游戏界面固定分成 **六个区域**，名字就下面这六个。以后不管是加东西、挪位置还是改大小，
先在这里找到区域名，再按下表去改对应的文件，不用满工程乱翻。

## 一、六个区域

| 区域名 | 在界面上的位置 | 根元素 | 里面装什么 | 谁来渲染 |
|---|---|---|---|---|
| **左侧栏** | 最左边一列 | `aside.panel.side-left` | 角色卡：名字、性别年龄身高职业、等级经验、技能点、生命 / 体力、负重（附轻载/中载/重载）、状态、属性、战斗、同伴。**属性 / 战斗 / 状态三块可以点标题收起**（「行动消耗 ×N」那一行已删：敏捷不再影响体力消耗，力竭在状态区里显示） | `renderChar()` → `#char-body` |
| **视图栏** | 中间一列的上半部分 | `main.main.view-panel` | 房间栏（地点 + 第几回合 + 右上角 **场景 / 背包 / 技能树** 三个页签），下面**同时只显示一个**：`#scene-panel` 是「场景」页签，**里面并排三块**——左边一列 `#view-map` 是**区域地图**（当前这层画成方块 + 下面的楼层切换条，可拖动平移 / 滚轮缩放），中间是 `#scene-body` 的 16×10 格子场景（地板 / 墙 / 障碍物，门和楼梯、人物、地上物品都用黑底白字的方块标出，玩家自己那格写着“我”；**颜色图例压在视图栏最下面一整条**、**点物品 / 人物的方块弹出「走过去 / 拿取（说话）/ 查看」小菜单**），右边一列 `.scene-side` 只有**时钟**；`#bag-panel` 是**背包**（翻页、点物品出菜单、拆分、堆叠、拖动装备）。按方向键就能走（背包页签里按方向键不会走） | `renderView()` 分派给 `renderScene()` / `renderBag()` / `renderSkillPanel()` |
| **移动栏** | 中间一列下半的**正中间** | `section.panel.move-panel` | **四个方向**（东 / 南 / 西 / 北）的九宫格 + 颜色说明。**有场景的地方一个方向 = 走一格**：绿＝那格能走、红＝那格有危险、暗＝走不通。**上下两个按钮已删**，上下楼改成点场景里的楼梯格走过去（控制台版还能打 `走 上`） | `moveSection()` → `#move-body` |
| **快捷区域1** | 移动栏**左边**那块 | `section.panel.quick-zone#quick-zone-1` | **装备栏**：主手 / 副手 / 头部防具 / 身体防具 / 手部防具 / 腿部防具 / 脚部防具 / 饰品 1 / 饰品 2 / 披风 / 背包，一共 **11** 个方框（「照明」位和「手部」护甲位都已删掉，手电筒改成拿在手上的武器）。拖物品到方框＝装备，把方框里的东西拖出去＝脱下，两只手之间拖动＝直接换手。**背包不在这儿**（在视图栏的「背包」页签） | `renderEquip()` → `#equip-body` |
| **快捷区域2** | 移动栏**右边**那块 | `section.panel.quick-zone#quick-zone-2` | **文字记录** + 最下面一行指令输入。**高度固定、消息在里面滚动**，不会把页面顶长。每次移动花掉多少体力也写在这里（引擎 `cmd_go` 追加的一句：`移动至（第 X 列，第 Y 行），体力消耗 N，用时 X 分钟`，没扣体力的那几步写 0） | `appendLines()` → `#log`，输入行是 `#cmd-form` |
| **右侧栏** | 最右边一列 | `aside.panel.side-right` | 只有四块：背包快捷栏（3 格，手动登记） / 休息 / 存档读档 / 系统。**时钟、「这里」列表、「打开背包」按钮和那几句说明都搬走了**（时钟进视图栏，开背包点视图栏右上角的「背包」页签，地上的东西在场景里点）。**拆分 / 堆叠不再放在这儿的系统栏**，改成点背包里的物品出菜单；系统栏里的「背包清单」按钮也删了（和视图栏的背包页签重复）；说明文字只留最短的一句（存档那块写「当前槽：N 号」），间距由 `style.css` 末尾的 `.side-right` 一段收紧，目标是窗口不用滚动就能看全。**系统栏最下面是「声音」那一块**（2026-10-03 加：音效音量滑条 + 音乐音量滑条 + 曲目下拉 + 静音按钮，`.audio-box` / `.audio-row` / `.audio-range` / `.audio-select`，代码在 `renderActions()` 里的 `audioSection()`，事件在 `bindAudioControls()`） | `renderActions()` → `#action-body` |

排布关系（一眼看懂）：

```
┌──────────┬────────────────────────────────────────┬──────────┐
│          │  视图栏：房间栏 + [场景 | 背包 | 技能树] 页签 │          │
│          │  ┌───────┬────────────────────┬───────┐   │          │
│  左侧栏   │  │ 地图   │ 16×10 格子（居中）   │ 时钟   │   │  右侧栏   │
│          │  │（一列， │ 颜色图例压在最下面   │（一列）│   │          │
│          │  │ 楼层条）│                    │       │   │          │
│          │  └───────┴────────────────────┴───────┘   │          │
│          ├────────────┬──────────────┬────────────┤          │
│          │  快捷区域1   │    技能栏     │  快捷区域2   │          │
│          │  （装备栏）   │ （10页×9格登记）│ （文字+输入） │          │
└──────────┴────────────┴──────────────┴────────────┴──────────┘
```

- 快捷区域1 和 快捷区域2 **一样宽**，分列技能栏两侧，所以技能栏自然居中。
- **「场景」页签里并排三块：地图 | 格子场景 | 时钟**，都占排版空间（不是浮层）。
  左右两块**一样宽**（都是 `--w-map`，`clamp(146px, 10vw, 210px)`），所以**中间的格子场景在整个视图栏里正中**，
  地图和时钟也一左一右对称、顶部同一条水平线。切到背包 / 技能树页签时整块 `#scene-panel` 一起 `hidden`
  （不然会浮在背包格子、技能树按钮上面挡住点击）。地图本身可以拖动平移、滚轮缩放（60%~300%，方块做小以后
  100% 就能看全一层，放大是看名字用），也可以点下面的楼层条换一层看；「复位」＝回到 100% 并把地图摆回人物那间房。
- **地图绝不允许压住场景格子**：它以前是绝对定位的浮层，贴左上角盖在场景上（1280 宽的窗口下实测
  盖住 61 个能点的格子，1500 宽盖住 45 个），2026-10-02 改成并排以后，在 1280×800 / 1366×768 /
  1500×950 / 1920×1080 四种尺寸下**一个格子都没被压住**（160 格全查过）。
  **代价是场景那一列窄了**：1500 宽时格子 43px → 27px（1920 宽时 47px、1280 宽时 14px）。
  想给场景多一点地方就调小 `--w-map`，**别再把地图改回浮层**（一改回去又会盖住格子）。
- **地图上写什么**（2026-10-03 改）：门格写**下一个地点的名字**（不是「南」「北」这种方向名），
  楼梯写「上楼 / 下楼」且是**绿字**（`.chip-stairs`，`#86df95`；门是暖白字 `.chip-door`）。
  名字由引擎的 `scene.door_names` 给，所以**不用走到门前就能看见**。
- **室外是每局随机生成的 10×10 街区，带探索迷雾**（见 `CLAUDE.md` 的「室外是每局随机生成的开放式街区」）：
  小地图上**没去过的格子画一个带斜纹的暗色「?」**（`.map-room.unknown`），**没见过的格子根本不画**；
  每一组（一栋楼 / 室外那一片）各算各的尺寸（`group.bounds`），楼里只有一两格，不会跟着 10×10 一起放大。
  **拖动范围只到「人物周围 6×6」**（`MAP_WINDOW`）——整座城不用一次装下。
- 移动栏和左右两块快捷区域**一样高**（同一排，同一根网格线），三块的**标题条也一样高**（同一套
  `.bottom-row .panel-head`：padding `3px 8px`，标题 12px，图标 13px，实测都是 27px）。
- **下排是固定高度**（`--h-bottom`），不再由内容决定：以前文字栏每多一条消息就把下排顶高一截，
  整页跟着变长；现在消息只在文字栏内部滚动。想让场景更高就调小 `--h-bottom`。
- **场景不靠滚动条看格子**：`.scene-wrap` 里 16×10 格子 `margin: auto` 上下左右都居中，图例是最后一条、
  横跨中间那一列。格子大小 `--cell` 按「中间那一列真正能用的宽高」算出来（`--w-mid` 中间列宽 −
  左右两列、`--h-scene` 留给格子的高度），列数由 JS 写在 `--scene-w` 上。
- **视图栏里没有上下滑动条**（2026-10-02 用户提的）：格子高度就是按 `--h-scene` 算的，以前那个常数差 2px，
  格子/图例就比可视区高 2px —— 于是视图栏多出一条上下滚动条。现在 `.scene-wrap` 是 `overflow-y: hidden`
  （竖着永不滚，横着窄窗口还可以滚），常数从 139px 提到 142px 留出余量；图例条的横向滚动条也只留功能、
  不画出来（`scrollbar-width: none` + `::-webkit-scrollbar`，一画就多占 15px 高度、又把格子挤出一条上下条），
  窗口 ≤1520px 时图例里最后那句「黑底白字方块…」直接收起来，图例永远只有一行 31px。
  窄窗口（约 ≤1250px 的两列布局）格子会卡在 13px 下限、格子比中间那列宽一点，那一列横向出现滚动条 ——
  这是有意的（宁可滚动，也不让地图压住格子）。

## 二、代码在哪

| 文件 | 里面对应什么 |
|---|---|
| `web/index.html` | 区域的骨架。每个区域的根元素都带 `data-region="区域名"`，搜这个名字就能定位。文件顶部有一段注释列出六个区域。 |
| `web/style.css` | `/* ---------- 布局：六大区域 ---------- */` 那一段。`:root` 里有 `--w-left` / `--w-right` / `--w-move` / `--h-bottom` / `--w-mid` / `--h-scene` / `--cell` 这几个尺寸变量。 |
| `web/app.js` | 顶部注释列出区域名；`el` 表里每个区域一个 `#id`；`renderChar()` / `renderView()`（再分 `renderScene()` / `renderBag()` / `renderSkillPanel()`）/ `renderEquip()` / `renderActions()` 分别负责左侧栏、视图栏、快捷区域1、移动栏+右侧栏。场景左上角的地图是 `renderMap()`（配套 `bindMap()`：拖动平移、滚轮缩放、点出口 / 楼层条 / 复位），右上角的时钟是 `renderClock()`（只画一份，装在 `#scene-panel` 里）；场景方块的小菜单是 `thingMenu()` / `placeThingMenu()` / `doSceneAction()`。 |
| `engine.py` | 场景数据与走动（`room_grid` / `_step` / `_travel` / `scene_state`）、一格一堆的背包（`add_item` / `take_item` / `cmd_split` / `cmd_stack`）、装备与背包分开存放（`cmd_equip` / `_switch_hand` / `cmd_unequip` / `stow` / `_to_ground`）。 |
| `data/world.json` | `map_areas`（地图的分层：现在是一组一组写的 —— 室外 / 公寓楼 / 社区医院 / 派出所 / 消防站，每组 `name` + `areas` 是它的一层层楼；老的平铺数组也认）；**`outdoor`（室外街区的生成规则：`size` 10×10、`fixed` 固定地点、`places` 随机地点、`spacing` 间距、`locked` 锁着的门、街道描述池，见 `outdoor.py`）**；每个房间的 `grid`：`tiles`（10 行 × 16 列）、`doors`（出口 → 门/楼梯坐标）、`objects`（物品 / NPC → 坐标），街道那种 `random_grid` 的房间地形是每局随机生成的；`random_items`（第一次进这个地点时随机生成，**最多 5 堆**、一堆几件按概率，见 `stats.SPAWN_GROUP_WEIGHTS` / `SPAWN_STACK_WEIGHTS`）和 `spawn_pools` + 地点的 `random_pool`（好几处地方共用一份随机物资清单，每种一个 `weight`）；物品的 `stack`（堆叠词条）、`tags`（食物标签）、`use`（使用效果）。装备位在 `armor_slots` / `gear_slots`（照明位已删；手电筒是 `weapon`，拿在手上）。 |

**约定**：任何元素只要带 `data-region="区域名"`，就表示它属于这个区域。新增块状界面时也照这个写，
以后用 `data-region` 就能一把搜出整个区域的代码。

## 三、现在各区域的实际尺寸

下面的数字是 1920×985 窗口下用无头浏览器实测的（不是估算）：

| 区域 | 宽度 | 高度 |
|---|---|---|
| 左侧栏 | 300px（`--w-left`） | 撑满窗口高（实测 957px） |
| 中间列 | 剩下的全部（`--w-mid`＝1244px） | 撑满窗口高 |
| 视图栏 | 1242px（中间列去掉 1px 边框） | 约 **569px** |
| 视图栏里的场景区 | 1242px | **520px**（图例条 31px 含在里面） |
| 场景格子的 16×10 格 | 756px（`--cell`＝45.4px × 16 格 + 15 道 2px 缝） | 472px（10 行 + 9 道缝） |
| 视图栏里的背包面板 | 1242px | **520px** |
| 场景左上角的地图 | 左边一列 `--w-map`（1920×1080 时 192px；1500 时 146px；可视窗口＝这一列去掉内边距和边框） | 一列 `--h-map`（1080 高时 340px；950 时 323px） |
| 场景右上角的时钟 | 约 191px（右边那一列一样的宽，`justify-content: flex-end` 贴右；列窄时「第 N 回合」折到第二行） | 33px（折行时 58px；和地图顶部同一条水平线） |
| 下排 | 同中间列 | **374px**（`--h-bottom`，固定） |
| 快捷区域1（装备栏） | 371px（与快捷区域2 完全相等） | 374px |
| 移动栏 | 468px | 374px（九宫格本身约 260px，多的算留白） |
| 快捷区域2（文字栏） | 371px | 374px（其中文字区 369×274，剩下是指令输入行） |
| 右侧栏 | 320px（`--w-right`） | 撑满窗口高（实测 957px） |
| 下排三块的标题条 | 各跟自己的面板一样宽 | **都是 27px**（标题 12px、图标 13px、padding `3px 8px`） |
| 视图栏里一格 | `--cell`（1920×1080 时 **48px**、1500×950 时 **27px**、1280×800 时 **14px**，原来写死 42px） | 同宽（正方形） |
| 背包里一格 | 66px 起（`minmax(66px, 1fr)` 自动填满） | 约 76px（里面是 44px 的黑底白字方块） |

> 数字怎么来的：用无头 Edge 打开页面，量每个 `[data-region]` 的 `getBoundingClientRect()`。
> `--cell` 是算出来的：`min((--w-mid − --w-map×2 − 90px)/16, (--h-scene − 18px)/10)`，上限 64px、下限 13px ——
> 也就是**中间那一列的宽和高各算一遍取小值**，而 `--h-scene` 里已经扣掉了房间栏和图例条。
> 改完布局一定要用无头浏览器量三件事：**160 个格子有没有被任何东西压住**（`elementFromPoint` 逐个查）、
> **格子中心是不是和视图栏中心对齐**（左右两列等宽就是靠这个验的）、`wrap.scrollHeight - wrap.clientHeight`。
> 窄屏（≤1080px）另有一套 `--w-map` / `--cell`。

## 四、想改的时候怎么改

| 想做的事 | 改哪里 |
|---|---|
| 左 / 右侧栏变宽变窄 | `style.css` 的 `--w-left` / `--w-right` |
| 移动栏变宽变窄 | `style.css` 的 `--w-move`（`clamp(300px, 24.5vw, 520px)`，跟着窗口宽度走） |
| 移动栏换成别的宽度比例 | `style.css` 的 `.bottom-row` 里那行 `grid-template-columns` |
| 快捷区域1 / 快捷区域2 不等宽 | 同上，把两个 `minmax(0, 1fr)` 改成 `2fr` / `1fr` 之类 |
| **下排（装备 / 移动 / 文字）的高度** | `style.css` 的 `--h-bottom`（`clamp(240px, 38vh, 400px)`）。**别改回 `auto`**：`.play-col` 的 `grid-template-rows` 第二行一变成 `auto`，文字栏就会被消息顶长 |
| 视图栏和下排的高度比例 | 同上 + `style.css` 的 `.play-col` 的 `grid-template-rows`（现在是 `minmax(180px, 1fr) var(--h-bottom)`） |
| 场景格子变大变小 | `style.css` 的 `--cell`（现在是 `min((--w-mid − --w-map − 86px)/16, (--h-scene − 18px)/10)`，上限 64px）。它是**算出来的**，所以改 `--w-left` / `--w-right` / `--h-bottom` / `--w-map` 之后格子会自己跟着变。想整体再大一点就把 `--h-scene` 里的常数（现在 142px，实测真实开销 141px，留 1px 余量）调小——**调小了格子/图例会超出可视区，视图栏就会冒出上下滑动条**（`overflow-y: hidden` 之后是被裁掉，更难发现），改完要用无头浏览器量一次 160 个格子有没有被压住、`wrap.scrollHeight - wrap.clientHeight` 是不是 0、图例底边有没有超出 `#scene-body` 的底边 |
| 左边那列地图 / 右边那列时钟 / 底部图例条 | `style.css` 的 `--w-map`（左右两列多宽，`clamp(146px, 10vw, 210px)`）、`--h-map`（地图那列多高）、`.view-map`（一列 flex：标题 + 可视窗口 + 楼层条，`align-self: flex-start` 所以不被拉高）、`.map-viewport`（`flex: 1`，占满剩下的地方，超出的裁掉）、`.map-room` / `.map-exit` / `.map-floor`（方块、出口胶囊、楼层条；楼层条固定 `flex: 0 0 44px`，一层和五层占一样高，地图可视窗口大小才不会跟着变；按钮上只写楼层，如 `4F` / `B1`）、`.scene-side` + `.view-clock`（右边那一列里的时钟，`justify-content: flex-end`；这一列窄，所以胶囊里的字允许折行）、`.scene-legend`（图例条，`margin: 0 -10px` 横跨中间那一列，横向滚动条不画出来；窗口 ≤1520px 时 `.lg-note` 那句说明收起来）。内容在 `web/app.js` 的 `renderMap()` / `renderClock()`；缩放范围是 `MAP_SCALE_MIN/MAX`（60%~300%）；拖动范围是 `MAP_WINDOW`（人物周围 6×6）；可视窗口大小**不归 JS 管**（`sizeMapViewport()` 只量一下 CSS 算出来的大小）。不让地图出现在背包 / 技能树页签里，靠 `renderView()` 里的 `hidden` 那一行 |

## 五、移动栏现在的样子

- 标题条和下排另外两块**完全一样**（`装备` / `移动` / `文字` 三条实测都是 27px：padding `3px 8px`、
  标题 12px、图标 13px），只跟着自己那块面板走，不再横跨整个中间列。
- 九宫格 3×3：北 在第一行正中间，西 / 地点名 / 东，南 在最后一行的正中间（四个角留空）；格子做得扁一点（内边距 4px、图标 15px）。**上下两个按钮已经删掉**：上下楼改成在场景里点楼梯那一格（走过去就换楼层），控制台版还能打 `走 上` / `走 下`。
- **有场景的房间一个方向 = 走一格**：绿＝那格能走（地板）、红＝那格有危险、显示地名＝那格是门 / 楼梯、暗色＝那格是墙或障碍物。
- **移动的体力消耗会写进快捷区域2 的文字里**：每走成功一步，正文里多一句
  `移动至（第 3 列，第 2 行），体力消耗 2，用时 1 分钟`；没凑满 10 步的那几步写 `体力消耗 0`；走不通（撞墙）不消耗体力，也就没有这一句。
  这句话在 `engine.py` 的 `_pay_move` / `_step` 里生成，所以网页版和控制台版都能看到。**不再说明方向，也不再区分室内外**。
  **口渴时这一步的消耗翻倍**（`stats.move_cost(overweight, thirsty)`，超重和口渴叠乘），触发的提示会另起一行接在正文后面。

## 六、快捷区域1（装备栏）怎么用

- **11 个方框**：主手、副手、头部防具、身体防具、手部防具、腿部防具、脚部防具、饰品 1、饰品 2、披风、背包。
  空位是虚线框，装了东西就是实线框 + 物品方块（方块里那行小字：护甲写护甲值、武器写类型和伤害骰、其它写重量）。
  面板里**不再有说明文字**（拖动规则写在方框的悬停提示里）。
- **拖**：把视图栏背包里的物品拖到方框上＝装备；两只手之间互相拖＝**直接换手**（不用先脱下来）；
  拖到方框以外的地方、或者拖到背包面板上＝脱下。
- 拖到不能装的位置会变红并提示，能装的位置变绿（前端 `canDrop` 按物品的 `slots` 判断）。
- 拖武器到主手 / 副手方框时，前端会在指令末尾带上 `主手` / `副手`（`装备 撬棍 副手`），引擎按指定的手放。
- 装备 **不会**出现在背包里（`game.inventory` 只装没穿在身上的）；脱下时回背包，**背包按负重上限算塞不下就丢在脚下**。
- **手电筒现在和开山刀一样是武器**（`weapon: {blunt, 1 只手, 1d4}`）：拖到主手 / 副手方框都能装，
  「照明」那个装备位已经删掉了。带没带手电筒才是下地下停车场的条件，**放背包里、拿在手上都算带着**。
  旧存档里装在照明位上的手电筒，读档时会自动收回背包（`Game._load_worn`）。

## 七、视图栏的「背包」页签怎么用

- 右上角三个页签 **场景 / 背包 / 技能树**：选中的页签底色变琥珀色，选择记在 localStorage（`fengcheng.view`），刷新后还停在同一页。
  打开背包时场景整块藏起来（**左边那列地图和右上角的时钟也在这一块里，一起收起来**，免得压住背包格子的点击），
  背包把视图栏占满（实测 1242×520）。
- **一格一堆**：带 `stack` 词条的物品最多摞 5 个，格子的右上角显示 `×n`；手动拆出来的那堆左上角有个
  **「散」**标记，表示它不会再被自动堆叠。方块里写物品名，下面一行小字是护甲值 / 伤害 / 重量。
- **点一下格子**才弹出菜单：查看 / 使用（能吃能喝的才有）/ 装备（能穿的才有）/ 拆分…（可堆叠且多于 1 个才有）/
  堆叠（背包里同种东西占了 ≥2 格才有；发 `堆叠 <物品名>`，把几堆合成一堆）/ 登记到快捷栏 / 丢弃 1 个 / 丢弃全部 ×n。
  菜单跟着那一格定位，点空白处或再点同一格收起。**拆分 / 堆叠以前放在右侧栏的系统栏里，现在只在这里出现。**
- **拆分**：弹出滑条 + 数字输入框（两个都改得了，互相跟着走），确认后发 `拆分 <堆号> <数量>`；
  拆出来的那堆 `auto=False`，不会被自动堆叠。
- **拖动**：拖到装备方框＝装备；拖到同种物品的格子上＝两堆合并（目标堆满了就不动）；拖到右侧快捷栏的格子上＝登记。
- **翻页**：每页 48 格，底部「‹ 上一页 / 第 n / m 页 · 共 k 格 / 下一页 ›」，到头的那一侧按钮自动禁用。
  翻页只是界面行为，不会去改背包顺序。
- 右侧栏的 **背包快捷栏固定 3 格，只能手动登记**：拖进去或者用菜单里的「登记到快捷栏」；格子里点 ✕ 取下。
  登记的物品不在背包里时格子写「没带」（不会自动拿背包里的东西来填）。**这块不再有「打开背包」按钮和说明文字**，
  开背包点视图栏右上角的「背包」页签。

## 七之二、场景里怎么拿东西 / 交谈

- 场景里**地上的物品和站在这里的人物都画成黑底白字方块**，鼠标点一下就弹出小菜单：
  物品是「走过去 / 拿取 / 查看」，人物是「走过去 / 说话 / 查看」（各自翻译成 `拿 X` / `查看 X` / `说话 X`）。
- **拿取 / 说话会自动走过去**：不在跟前时先按 BFS 找一条路连续发 `走 <方向>`，走到那一格才发
  `拿 X` / `说话 X`（`doSceneAction` → `scenePath` + `walkAlong(steps, after)`）；已经在跟前就直接发指令。
  引擎那边照样有**走到跟前**的限制（同一格或相邻一格，斜角也算），所以绕不过去：真走不到会提示
  「X 在（第 a 列，第 b 行），你得先走到那一格旁边再拿」。**查看不受限制，可以远程看。**
- **「走过去」只移动、不拾取**：同样走 BFS 那段路（`doSceneAction('move')`），走到那件东西 / 那个人所在的格子；
  已经站在那一格上时菜单里不显示这一项。
- 点带东西的格子**不会走路**（先出菜单）；点别的空格子先把菜单收起来，再点一次才走。
- **人和东西挤在同一格**（`放下` 就是丢在自己脚下）时，那一格画的是东西的名字、小字写「我在这里」，
  不然东西就被“我”挡住了、再也拿不回来。
- 右侧栏原来的「这里」列表已经删掉，它的功能全在这套小菜单里；`engine.scene_state()` 的 `things`
  是数据来源（每条带 `id` / `name` / `kind` / `x` / `y`；地上物品的 `id` 是 `g` + 序号，
  因为同一种东西可能在地上摆好几件，例如便利店里的肉罐头）。

## 八、这份文档的用途

这份文档就是界面区域的“地图”。**改界面之前先在这里查区域名和对应选择器**；改完顺手把上面表格里的
数字更新一下（第三节），下次就不用重新量了。区域名一旦定下就不要再改，代码注释、`data-region`、
本文件都靠它对齐。

改完 `web/` 里的文件**刷新页面就行**（这些文件每次请求都重新读盘）；改了 `webui.py` 或 `engine.py` 才需要重启服务。
不过注意：**关掉标签页 = 关掉游戏**（服务端等十来秒确认没有别的页面在看，就结束这一局并退出服务），
调试时别顺手把页面关掉；刷新是安全的，有宽限期。改界面时的规矩和六个区域的背景见 `CLAUDE.md` 的「界面」一节。
