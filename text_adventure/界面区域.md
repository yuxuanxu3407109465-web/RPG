# 界面区域命名

网页版的游戏界面固定分成 **六个区域**，名字就下面这六个。以后不管是加东西、挪位置还是改大小，
先在这里找到区域名，再按下表去改对应的文件，不用满工程乱翻。

## 一、六个区域

| 区域名 | 在界面上的位置 | 根元素 | 里面装什么 | 谁来渲染 |
|---|---|---|---|---|
| **左侧栏** | 最左边一列 | `aside.panel.side-left` | 角色卡：名字、性别年龄身高职业、生命 / 体力、等级经验、属性、负重、装备、同伴 | `renderCharacter()` → `#char-body` |
| **文字栏** | 中间一列的上半部分 | `main.main` | 房间栏（地点 + 第几回合）、正文滚动区、指令输入行。**每次移动花掉多少体力也写在这块正文里**（引擎 `cmd_go` 追加的一句） | `appendLine()` → `#log` |
| **移动栏** | 中间一列下半的**正中间** | `section.panel.move-panel` | 六向九宫格 + 颜色说明 | `moveSection()` → `#move-body` |
| **快捷区域1** | 移动栏**左边**那块 | `section.panel.quick-zone#quick-zone-1` | 预留，暂时留空 | 还没有（容器已就位） |
| **快捷区域2** | 移动栏**右边**那块 | `section.panel.quick-zone#quick-zone-2` | 预留，暂时留空 | 还没有（容器已就位） |
| **右侧栏** | 最右边一列 | `aside.panel.side-right` | 顶部紧凑时钟，下面依次是 这里 / 背包快捷栏 / 休息 / 存档读档 / 系统 | `renderActions()` → `#action-body` |

排布关系（一眼看懂）：

```
┌──────────┬────────────────────────────────────────┬──────────┐
│          │              文字栏                     │          │
│          │   （房间栏 + 正文 + 指令输入，占 2/3 高）    │          │
│  左侧栏   ├────────────┬──────────────┬────────────┤  右侧栏   │
│          │  快捷区域1   │    移动栏     │  快捷区域2   │          │
│          │  （留空）    │  （六向九宫格） │  （留空）    │          │
└──────────┴────────────┴──────────────┴────────────┴──────────┘
```

- 快捷区域1 和 快捷区域2 **一样宽**，分列移动栏两侧，所以移动栏自然居中。
- 移动栏和左右两块快捷区域**一样高**（同一排，同一根网格线）。
- 文字栏和下排的高度比例约为 **70 : 30**。

## 二、代码在哪

| 文件 | 里面对应什么 |
|---|---|
| `web/index.html` | 区域的骨架。每个区域的根元素都带 `data-region="区域名"`，搜这个名字就能定位。文件顶部有一段注释列出六个区域。 |
| `web/style.css` | `/* ---------- 布局：六大区域 ---------- */` 那一段。`:root` 里有 `--w-left` / `--w-right` / `--w-move` 三个宽度变量。 |
| `web/app.js` | 顶部注释列出区域名；`el` 表里每个区域一个 `#id`；`renderActions()` 说明谁渲染到哪个区域。 |

**约定**：任何元素只要带 `data-region="区域名"`，就表示它属于这个区域。新增块状界面时也照这个写，
以后用 `data-region` 就能一把搜出整个区域的代码。

## 三、现在各区域的实际尺寸

下面的数字是 1920 宽窗口下用无头浏览器实测的（不是估算）：

| 区域 | 宽度 | 高度 |
|---|---|---|
| 左侧栏 | 300px（`--w-left`） | 撑满窗口高 |
| 中间列 | 剩下的全部（约 1214px） | 撑满窗口高 |
| 文字栏 | 同中间列 | 约 614px（占中间列 70%） |
| 下排 | 同中间列 | 约 **259px**（占中间列 30%） |
| 快捷区域1 | 361px（与快捷区域2 完全相等） | 259px |
| 移动栏 | 463px | 259px |
| 快捷区域2 | 361px | 259px |
| 右侧栏 | 320px（`--w-right`） | 撑满窗口高 |
| 移动栏的横幅 | 463px（跟移动栏一样宽，不再横跨中间列） | **27px**（“移动”12px） |

下排的 259px 是这么凑出来的：横幅 27 + 面板内边距 11 + 九宫格三行（每行 60）+ 行间距 10 + 说明文字一行 ≈ 259。
想再矮就从这几项里挑一个减（见下一节）。

## 四、想改的时候怎么改

| 想做的事 | 改哪里 |
|---|---|
| 左 / 右侧栏变宽变窄 | `style.css` 的 `--w-left` / `--w-right` |
| 移动栏变宽变窄 | `style.css` 的 `--w-move`（`clamp(300px, 24.5vw, 520px)`，跟着窗口宽度走） |
| 移动栏换成别的宽度比例 | `style.css` 的 `.bottom-row` 里那行 `grid-template-columns` |
| 快捷区域1 / 快捷区域2 不等宽 | 同上，把两个 `minmax(0, 1fr)` 改成 `2fr` / `1fr` 之类 |
| 文字栏和下排的高度比例 | `style.css` 的 `.play-col` 的 `grid-template-rows`（现在是 `minmax(180px, 1fr) auto`） |
| 下排整体再矮一点 | `style.css` 里 `.move-panel .dir` 的 `padding`（现在 `4px`）和 `.move-panel .dir .ico`（现在 15px）—— 每减 1px，三行一共矮 6px |
| “移动”这两个字变大变小 | `style.css` 的 `.move-panel .move-head h3` 的 `font-size`（现在是 12px） |
| 移动栏那条横幅变高变矮 | `style.css` 的 `.move-panel .move-head` 的 `padding`（现在是 `3px 8px`）。**注意**：一定要带 `.move-panel` 这一层，因为文件后面还有一条 `.panel-head { padding: 11px 14px }`，选择器权重一样时后写的会赢——之前就是踩了这个坑，横幅一直是 46px 高、字也是 14px。 |
| 往快捷区域1 里加内容 | 往 `#quick-zone-1` 里渲染（`app.js` 的 `el.quickZone1` 已经取好了），再把 `.quick-zone` 的虚线框去掉 |
| 移动消耗的体力写在哪儿 | 引擎 `engine.py` 的 `cmd_go`：移动成功后往正文末尾追加一句 `（移动消耗 N 点体力：旧 → 新/上限，用时 X 分钟）`，网页和控制台共用这一句 |
| 窄屏（≤1080px）的表现 | `style.css` 最下面那段 `@media (max-width: 1080px)`：改成单列堆叠，快捷区域先隐藏 |

## 五、移动栏现在的样子

- 横幅（标题条）比其它面板头矮一截、窄一条：只跟着移动栏走，不再横跨整个中间列；
  “移动”两个字 12px，地图小图标 13px，整条 **27px** 高。
- 九宫格 3×3：上 / 北 / 下 一行，西 / 地点名 / 东 一行，南 在最后一行的正中间；格子做得扁一点（内边距 4px、图标 15px）。
- 格子颜色：绿＝可以走（显示通往哪里）、红＝那边有危险、暗＝不知道，下面一行小字是这句说明。
- **移动的体力消耗会写进文字栏**：每走成功一步，正文末尾多一句
  `（移动消耗 2 点体力：390 → 388/390，用时 1 分钟）`；走不通（撞墙）不消耗体力，也就没有这一句。
  这句话在 `engine.py` 的 `cmd_go` 里生成，所以网页版和控制台版都能看到。

## 六、这份文档的用途

这份文档就是界面区域的“地图”。**改界面之前先在这里查区域名和对应选择器**；改完顺手把上面表格里的
数字更新一下（第三节），下次就不用重新量了。区域名一旦定下就不要再改，代码注释、`data-region`、
本文件都靠它对齐。

改完 `web/` 里的文件**刷新页面就行**（这些文件每次请求都重新读盘）；改了 `webui.py` 或 `engine.py` 才需要重启服务。
